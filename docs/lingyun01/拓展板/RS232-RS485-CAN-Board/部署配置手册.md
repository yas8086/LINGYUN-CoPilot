## 一、接口总览与设备分配

| 板上接口 | 芯片方案 | Linux 设备 | 本项目设备 | 波特率 |
|---|---|---|---|---|
| **2×RS485** | SC16IS752 + SP485 | `/dev/ttySC0`, `/dev/ttySC1` | RS485_1→集中器、RS485_2→12S电源 | 300~921600 |
| **1×CAN** | MCP2515 + SN65HVD230 | `can0` | BMS + MPPT + DCDC 共线 | 250kbps |
| **1×CAN FD** | MCP2518FD + MCP2562FD | `can1` | 预留 | 250k/5M FD |
| **1×RS232** | 板载UART + SP3232EEN | `/dev/ttyAMA0` | 调试 | 115200 |

### 实际接线映射（本机已验证）

| 符号链接 | 指向 | 对应板上接口 | 设备 | 是否需别名 |
|---|---|---|---|---|
| `/dev/airship_485` | → `/dev/ttySC0` | **RS485_1** | 温度压力集中器（Modbus RTU 9600） | ✅ 需要 |
| `/dev/airship_backup_bms` | → `/dev/ttySC1` | **RS485_2** | 12S 备用电源 BMS（北辰协议 9600） | ✅ 需要 |
| `/dev/airship_debug_rs232` | → `/dev/ttyAMA0` | **RS232** | 调试口 | ✅ 需要 |
| `can0` | — | CAN | BMS(102S)+MPPT+DCDC（250k） | ❌ 直接用 can0 |
| `can1` | — | CAN FD | 预留 | ❌ 直接用 can1 |

> **设备接口归属说明**
> - **走 CAN 的设备**（102S主BMS、MPPT、DCDC）：挂微雪板 CAN 口 → `can0`，直接用 `can0` 标识，无需 udev 符号链接
> - **走网口的设备**（飞控）：接交换机，用网络协议（MAVLink/IP）访问，无需 udev 符号链接
> - **只有走串口/485 的设备**（集中器、12S备用电池、RS232调试）才需要 udev 稳定别名

## 二、config.txt 配置

配置文件：`/boot/firmware/config.txt`

### 关键配置段（追加到 [all] 段）

```ini
[all]
# 启用 SPI（微雪板 RS485/CAN 依赖 SPI）
dtparam=spi=on

# 微雪 RS232-RS485-CAN-Board
enable_uart=1                      # RS232 用板载 UART
dtoverlay=i2c0                     # 官方要求
dtoverlay=spi1-3cs                 # SPI1 三片选（SC16IS752 用）
dtoverlay=sc16is752-spi1,int_pin=25   # 2×RS485 → /dev/ttySC0, ttySC1
dtoverlay=mcp2515,spi0-0,oscillator=16000000,interrupt=23   # 1×CAN → can0
dtoverlay=mcp251xfd,spi0-1,interrupt=24                      # 1×CAN FD → can1
```

> **来源**：官方 Wiki "Modify config.txt" 章节，唯一正确配置。
> 注意：这是 **RS232-RS485-CAN-Board** 的专属配置，与另一款 **RS485 CAN HAT (B)** 的 overlay 不同（后者是 `sc16is752-spi1` + `mcp2515-can0,oscillator=8000000`），不要混用。

### 验证配置生效（重启后）

```bash
sudo reboot

# RS485 (SC16IS752)
ls -l /dev/ttySC*
dmesg | grep -i sc16is        # 期望: ttySC0/ttySC1 is a SC16IS752

# CAN (MCP2515) / CAN FD (MCP2518FD)
dmesg | grep -i mcp251        # 期望: MCP2515 successfully initialized
                              #       MCP2518FD ... successfully initialized
```

## 四、udev 稳定符号链接规则

### 文件位置（tools/）

- [70-airship-usb.rules](../../../../tools/70-airship-usb.rules) — USB 串口（4G 等）
- [71-airship-extboards.rules](../../../../tools/71-airship-extboards.rules) — **微雪板 SPI 串口 + CAN**

### 71 号规则关键内容

```ini
# ---- 微雪板 RS485_1 (ttySC0) → 温度压力集中器 ----
SUBSYSTEM=="tty", ACTION=="add", KERNEL=="ttySC0", \
  SYMLINK+="airship_485", GROUP="dialout", MODE="0660"

# ---- 微雪板 RS485_2 (ttySC1) → 12S 备用电源 ----
SUBSYSTEM=="tty", ACTION=="add", KERNEL=="ttySC1", \
  SYMLINK+="airship_backup_bms", GROUP="dialout", MODE="0660"

# ---- 微雪板 RS232 (ttyAMA0) → 调试口 ----
SUBSYSTEM=="tty", ACTION=="add", KERNEL=="ttyAMA0", \
  SYMLINK+="airship_debug_rs232", GROUP="dialout", MODE="0660"
```

> **重要说明**：
> - 集中器原走 USB-RS485（FTDI `/dev/airship_485`）。改接微雪板后，`/dev/airship_485` 由 ttySC0 提供，**节点代码/参数无需改动**。旧 FTDI 的 `airship_485` 规则已在 70 号文件中注释，避免符号链接冲突。
> - **CAN 接口（can0/can1）不建立符号链接**：直接用原生接口名 `can0`/`can1`（`ip link` 管理），无需 `/dev/airship_can_*` 别名。
> - **未启用设备不建规则**：`/dev/ttyAMA2`（板载备用 UART）因 config.txt 未加 `dtoverlay=uart2` 而不存在，其别名规则已移除。

### 部署命令

```bash
sudo cp tools/70-airship-usb.rules /etc/udev/rules.d/70-airship-usb.rules
sudo cp tools/71-airship-extboards.rules /etc/udev/rules.d/71-airship-extboards.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty --action=add
```

### 验证

```bash
ls -l /dev/airship_485 /dev/airship_backup_bms /dev/airship_debug_rs232
# 期望:
#   /dev/airship_485 -> ttySC0
#   /dev/airship_backup_bms -> ttySC1
#   /dev/airship_debug_rs232 -> ttyAMA0
```

> ⚠️ 若触发后符号链接消失，用 `--action=add` 重新触发（不要用 `--action=change`）：
> ```bash
> sudo udevadm trigger --subsystem-match=tty --action=add
> ```

## 五、CAN 接口开机自启

> CAN 接口（can0/can1）使用**原生接口名**，由 systemd 服务自启，**无需 udev 符号链接**。

### 相关文件（tools/systemd/）

- [airship-can.service](../../../../tools/systemd/airship-can.service) — systemd 服务
- [airship-can-up.sh](../../../../tools/systemd/airship-can-up.sh) — CAN 上线脚本
- [airship-io-check.sh](../../../../tools/systemd/airship-io-check.sh) — 全接口自检脚本

### 波特率配置文件

`/etc/default/airship-can`（can0=250kbps，匹配 BMS/MPPT/DCDC）：

```bash
# can0: BMS(102S) + MPPT + DCDC 共线, 250kbps
CAN_BITRATE=250000
# can1: CAN FD 预留 (数据段)
CAN_DBITRATE=5000000
# 1 = can1 开启 CAN FD 模式
CAN_FD_ON=1
```

### 部署命令

```bash
sudo cp tools/systemd/airship-can-up.sh /usr/local/bin/airship-can-up.sh
sudo chmod +x /usr/local/bin/airship-can-up.sh
sudo cp tools/systemd/airship-can.service /etc/systemd/system/airship-can.service
sudo systemctl daemon-reload
sudo systemctl enable --now airship-can
```

### 验证

```bash
systemctl status airship-can
ip -d link show can0      # 期望 bitrate 250000, state UP
ip -d link show can1      # 期望 bitrate 250000 dbitrate 5000000 fd
```

## 六、网络方案（交换机拓扑）

### 6.1 拓扑总览

```
【机载侧】                                       无线链路(MAC网桥)      【地面侧】
飞控 ──UART1(TTL)── 数传L33 ═══════════════════════ 地面数传 ──串口── QGC(遥控遥测)
飞控 ──ETH──────────┐
树莓派 ──ETH────────┼── 交换机 ── 数传L33(网口) ═══ 地面数传网口 ── 地面电脑
摄像头×N ──ETH──────┘
```

- **数传 L33** 是"多口汇聚转发"数传：串口数据（飞控 Telem1）与网口数据（交换机）各自独立经无线转发到地面端
- 网口是 **MAC 层透传（网桥）**：机载网段被桥接，地面端可访问机载所有设备（树莓派/飞控/摄像头）

### 6.2 设备接线与 IP 规划

| 设备 | 接口 | IP | 作用 |
|---|---|---|---|
| 数传 L33（机载） | UART1=飞控Telem1；网口=交换机 | 网口 `192.168.10.254` | 无线链路桥 |
| 数传 L33（地面） | 串口=QGC；网口=地面电脑 | — | 地面接入 |
| **树莓派 eth0** | 交换机 | `10.41.10.100/24` + `192.168.10.100/24` | 双网段接入 |
| 飞控 | ETH→交换机 | `10.41.10.2` | MAVLink |
| 摄像头×N | ETH→交换机 | 按摄像头分配 | IP 拉流 |

### 6.3 树莓派 eth0 双 IP 配置（已固化）

树莓派同时连飞控（10.41.10.x）和数传（192.168.10.x），eth0 需绑定两个网段 IP。

**当前生效配置**（NetworkManager / netplan）：

```yaml
# /etc/netplan/ 下 eth0 连接配置（实际路径 90-NM-*.yaml）
ethernets:
  eth0:
    addresses:
    - "10.41.10.100/24"      # 连飞控
    - "192.168.10.100/24"    # 连数传网口
    dhcp4: false
```

**验证**：
```bash
ip -4 addr show eth0
# 期望同时看到 10.41.10.100 和 192.168.10.100

ping -c2 10.41.10.2        # 飞控
ping -c2 192.168.10.254    # 数传网口
```

### 6.4 数传网口 UDP 转串口（地面站访问飞控）

数传手册定义（UDP 转串口）：

| 数传递道 | UDP 端口 |
|---|---|
| 串口1（飞控） | **14550** |
| 串口2 | **14551** |
| SBUS | **14552** |

- 地面站发送 UDP 到数传网口 → 无线 → 机载数传 → 转成串口给飞控
- 机载树莓派如需测数传链路：

```bash
# 经数传网口向飞控发心跳/收遥测(已验证)
cd /tmp && python3 << 'EOF'
from pymavlink import mavutil
import time
mav = mavutil.mavlink_connection('udpout:192.168.10.254:14550',
                                 source_system=255, source_component=190)
mav.mav.heartbeat_send(0, 0, 0, 0, 0)
mavrx = mavutil.mavlink_connection('udpin:0.0.0.0:14550')
start = time.time(); n = 0
while time.time() - start < 3:
    m = mavrx.recv_match(blocking=False)
    if m: n += 1
print(f"经数传收到 {n} 条 -> 链路OK" if n else "无数据")
EOF
```

### 6.5 遥测下传：串口 + UDP 双发（link_node）

树莓派遥测数据（BMS/MPPT/DCDC/飞控/集中器等，聚合为 `0xAA 0x55 [JSON]\n` 帧）由 `link_node` 下传，支持**串口 + 数传网口 UDP 双发冗余**：一路故障不影响另一路。

#### 6.5.1 双链路构成

| 通道 | 出口 | 目标 | 说明 |
|---|---|---|---|
| 串口 | `serial_device`（如 `/dev/airship_link` / 调试用 ttyAMA0） | 地面 Qt 上位机 | 传统串口数传 |
| **UDP** | `udp_host:udp_port`（默认 `192.168.10.200:20000` = 地面站固定 IP） | 地面监听端（同网段） | 定向单播，经数传透传直达地面 |

#### 6.5.2 参数配置（`airship_params.yaml` → `link_node`）

```yaml
link_node:
  ros__parameters:
    serial_device: "/dev/airship_link"   # 串口数传递备
    baud_rate: 115200
    tx_rate_hz: 5.0                       # 遥测下传频率
    reconnect_ms: 2000                    # 串口重连周期
    udp_host: "192.168.10.200"           # UDP 目标: 地面站固定单播 IP; 留空则仅串口
    udp_port: 20000                      # UDP 目标端口(高位端口, 避开数传映射段)
```

> **目标与端口选择**：
> - **目标 IP**：默认 `192.168.10.200`（地面站固定 IP，定向单播，数据只发该机，干净安全）。**不要发到 `192.168.10.254`**（那是数传设备自身 IP，数据会被数传当管理流量吃掉，不转发）。联调期若地面 IP 不固定，可改用子网广播 `192.168.10.255`（任意同网段监听端可收，但全网可见、含敏感数据）。
> - **端口**：必须避开数传端口映射段 **14550/14551/14552**（预留给地面站-飞控 UDP→串口映射）。用高位端口（默认 **20000**）确保普通 UDP 业务走数传 **MAC 网络透传**（Insight Link 手册 4.1.3）直达地面。机载 `udp_port` 须与地面监听端一致。

#### 6.5.3 地面接收验证（机载发 → 地面收）

机载侧先确认 UDP 通道打开（link_node 日志显示 `UDP 下传已启用`）；地面监听验证：

```bash
# 地面电脑: 监听 20000, 应收到 0xAA 0x55 [JSON]\n 帧
nc -u -l 20000
# 或
python3 -c "
import socket
s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.bind(('', 20000)); s.settimeout(10)
try:
    data, _ = s.recvfrom(4096)
    print('收到', data[:60], '...')
except socket.timeout:
    print('超时无数据')
"
```

> **闭环自测（无需地面）**：机载本机 `nc -u 127.0.0.1 <port>` 或单测 `test_udp_sender` 已用 loopback 验证 UDP 收发链路。实机验证需确保机载 eth0 已配 `192.168.10.100/24`（见 6.3），且能 `ping 192.168.10.254`。

### 6.6 带宽注意事项

- L33 无线带宽 ~**17.2Mbps**（自适应），地面端所有访问共享此带宽
- 避免同时拉多个摄像头高清流（会占满带宽、拖垮遥控链路）
- 数传主要承担：飞控遥控/遥测 + 树莓派轻量数据上报；摄像头视频建议走独立图传

## 七、接口通讯验证

### RS485 — 集中器（Modbus RTU 9600，从机地址 1）

```python
import serial, time, struct

def modbus_crc(frame):
    crc = 0xFFFF
    for b in frame:
        crc ^= b
        for _ in range(8):
            crc = (crc >> 1) ^ 0xA001 if crc & 1 else crc >> 1
    return crc

def build_read(addr, reg, n=2):
    f = bytes([addr, 0x03]) + struct.pack('>HH', reg, n)
    return f + struct.pack('<H', modbus_crc(f))

s = serial.Serial('/dev/airship_485', 9600, timeout=1.0)
s.reset_input_buffer()
s.write(build_read(1, 0x76C1, 2))   # 读 30393 起 2 个寄存器
time.sleep(0.5)
print("响应:", s.read(64).hex())
```

**已验证**：`/dev/airship_485` 收到集中器响应，链路正常。

### CAN — candump 监听

```bash
sudo ip link set can0 up type can bitrate 250000
sudo candump can0 -n 20    # 接 BMS/MPPT/DCDC 后应收到报文
```

## 八、常见问题

| 现象 | 排查 |
|---|---|
| 无 `/dev/ttySC*` | 确认 `dtoverlay=sc16is752-spi1,int_pin=25` 在 config.txt；`dmesg\|grep sc16is` |
| 无 can0/can1 | 确认 `dtoverlay=mcp2515,spi0-0` / `mcp251xfd,spi0-1`；IRQ 引脚 23/24 |
| 集中器 485 不通 | 先测 `ttySC0` 和 `ttySC1` 哪个有响应；A/B 对调；确认共地(GND) |
| can0 无报文 | 确认 BMS/MPPT/DCDC 已接 CAN_H/CAN_L；波特率 250k；120Ω 终端电阻（跳线帽） |
| 符号链接消失 | 用 `sudo udevadm trigger --subsystem-match=tty --action=add` 重新触发 |
