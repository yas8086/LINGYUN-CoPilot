# 4G 模块接入与调试指南

> 适用硬件：微雪4G拓展板 + SIM7600G-H-M2 模块（树莓派5）
> 环境：Ubuntu 24.04 + ModemManager + NetworkManager
> 说明：本指南面向动手学习者，逐步给出命令并讲解原理。

## 一、上网链路总览

SIM7600G-H 要联网，需依次通过 4 道关，调试时按此顺序排查：

```
[SIM卡] → ① SIM识别 → ② 网络注册 → ③ 数据连接 → ④ wwan0 拿到IP → 能上网
          (CPIN)     (CREG/LTE attach)  (QMI拨号 + APN)    (ping 验证)
```

**为什么是这个顺序？** 每一步都依赖上一步：没有 SIM 就不会注册网络，不注册就没有数据连接，没有数据连接 wwan0 就不会 UP。因此先解决第①关。

## 二、系统识别确认（模块是否被系统看到）

模块上电接好后，先确认系统识别正常：

```bash
lsusb                       # 应出现 1e0e:9001 Qualcomm/SimTech
ls -l /dev/ttyUSB*          # 应出现 ttyUSB0-4
ip -br addr                 # 应出现 wwan0（QMI 网络接口）
readlink /sys/class/net/wwan0/device/driver   # 应为 qmi_wwan
```

| 检查项 | 正常现象 | 异常排查方向 |
|--------|----------|--------------|
| USB 枚举 | `1e0e:9001` | 接触/供电/驱动缺失 |
| 串口 | `ttyUSB*` | USB 驱动 `option` 未加载 |
| 网络口 | `wwan0` | QMI 驱动 `qmi_wwan` 未加载 |
| ModemManager | 服务 active | `systemctl status ModemManager` |

## 三、第①关：SIM 卡识别（最常见卡点）

### 操作
1. **断电插卡**：拔模块电源，找到板上 SIM 卡槽，金属触点朝下（朝板子），按缺口方向轻推到位。
2. 确认是 **nano-SIM**，且 **已激活、未停机**。
3. 上电后重新插拔 USB 或重启。

### 验证
```bash
mmcli -L                                    # 列出所有模块，记住编号（不固定，可能是 0/5/...）
mmcli -m <编号> | grep -A3 "SIM"            # 查看 SIM 卡槽状态；识别到卡会显示 "slot 1: [SIM card]"
mmcli -m <编号> | grep -A3 "Status"         # 查看模块整体状态；插卡成功应为 registered（而非 failed）
```

### 判断
- 正确插卡后：`SIM slot paths` 从 `none` 变为 `slot 1: [SIM card]`；`state` 从 `failed / sim-missing` 变为 `registered`。
- 仍报 `sim-missing`：多为**接触不良或方向反**，属物理问题，软件查不出。

### 原理
USB 串口只是物理通道，ModemManager 通过 AT 命令发 `AT+CPIN?` 查询 SIM 锁状态。模块读不到芯片就会把整机状态置为 `failed sim-missing`。

## 四、第②关：网络注册 + 信号

SIM 识别成功后自动搜网，验证：

```bash
sudo mmcli -m <编号> --command='AT+CPIN?'    # +CPIN: READY
sudo mmcli -m <编号> --command='AT+CREG?'    # +CREG: 0,1 或 0,5（已注册）
sudo mmcli -m <编号> --command='AT+CSQ'      # 信号强度，>=15 即可联网
```

> `--command` 发 AT 需要 PolicyKit 授权，通常要加 `sudo`。

**原理**：
- `AT+CPIN?`：SIM 卡 PIN 锁状态，`READY` 表示卡可用。
- `AT+CREG?`：网络注册状态，`1`（已注册）/`5`（漫游注册）算成功。
- `AT+CSQ`：信号强度（RSSI）。**4G 必须接外部天线**，否则这关会失败。

**为什么必须注册网络？** 模块上电后与基站并非天然连接，需主动"刷存在感"：

```
模块开机 → 搜频段(找基站) → 向核心网发起入网 → 运营商鉴权(验证SIM合法性) → 位置登记 → "已注册"
```

- **鉴权**：运营商用 SIM 卡内密钥"对暗号"，验证卡是否合法（是否欠费/停机）。
- **位置登记**：网络要知道你当前在哪个基站范围，别人才能找到你。
- **分配资源**：注册成功才分配临时身份（TMSI）。`AT+CREG?` 即查询"是否注册成功"。

## 五、第③④关：建立数据连接 + 验证联网

推荐用 ModemManager + NetworkManager（系统均已启用，QMI 拨号最稳）。

### 方式 A：nmcli（推荐、简单）
```bash
nmcli device                          # 确认 wwan0 被 NetworkManager 接管
# 选中 wwan0 配置 APN 后连接
nmcli connection up <连接名>           # 激活该 4G 连接，触发注册+拨号
```

### 方式 B：mmcli 手动拨号（便于学习、可控）
```bash
sudo mmcli -m <编号> --simple-connect="apn=cmnet"   # APN 按运营商填
ip addr show wwan0                                   # 应出现 inet 私网IP
```

> ⚠️ **常见坑**：`--simple-connect` 会打印 `successfully connected`，但 `wwan0` 可能仍是 **DOWN / 无 IP**。原因：ModemManager 只建立数据会话，**接口 IP 的配置与拉起**这一步要交给 NetworkManager。此时 `ping` 会报 `Network is unreachable`。
>
> **正确做法**：让 NetworkManager 接管（持久、开机自动）：
> ```bash
> sudo mmcli -m <编号> --simple-disconnect        # 断开手动会话，交给 NM
> sudo nmcli connection add type gsm ifname cdc-wdm0 con-name 4g apn cmnet   # 建 4G 连接
> sudo nmcli connection up 4g                       # 激活，自动配置 wwan0 IP
> ```
> 之后 `wwan0` 出现 `inet 10.x.x.x` 即成功。

### 验证联网
```bash
ip addr show wwan0                    # wwan0 应为 UP 且有 IP
ping -I wwan0 -c 4 8.8.8.8            # 走 wwan0 出口 ping 外网
ping -I wwan0 -c 4 baidu.com          # 验证 DNS
curl --interface wwan0 -s ifconfig.me # 输出公网IP即成功
```

**原理**：
- **APN 是必须项**：运营商分配的接入点名。移动 `cmnet`、电信 `ctnet`、联通 `3gnet`。APN 错 → 能注册但建立不了数据上下文。
- **`-I wwan0` / `--interface wwan0`**：强制从 wwan0 出去，避免误走 Wi-Fi（如 `192.168.1.59`），否则测的是 Wi-Fi 而非 4G。

**什么叫做"拨号"？** 这里的"拨号"是历史叫法（源自上古 Modem 拨电话音上网），本质是**建立一条 IP 数据承载通道**：

```
IP数据包 → 手机/模块 → 基站 → 运营商核心网(GGSN/PGW) → 互联网
                         └──────── 这条双向通道 = "拨号" ────────┘
```

模块向网络申请一个数据上下文（PDP context），拿到一个 IP，并约定 APN 与封装方式。成功则 `wwan0` UP 并出现 `inet 10.x.x.x`。

**为什么手机插卡就能用，这个模块却要手动拨号？** 手机把"注册+自动拨号"全自动化了；模块则分开处理：**注册已由 ModemManager 自动完成，拨号仍需手动**。

| | 手机 | 本项目（树莓派 + ModemManager） |
|---|---|---|
| 注册网络 | 开机自动 | 自动（ModemManager 已代办） |
| 数据连接 | 系统自动连 | 需手动配 APN 并拨号 |
| 谁来做 | 手机系统替你干了 | 注册系统替你干，拨号你来发起 |

**为什么注册自动、拨号却要手动？**
- **注册（网络报到/鉴权）**：ModemManager 检测到合法 SIM 后会自动触发，无需干预——这就解释了为什么你什么都没做，`mmcli -m 7` 却显示 `state: registered`。
- **拨号（建立数据通道）**：ModemManager 默认**不自动建数据连接**，因为需要指定 APN、且会消耗流量，所以留给你或 NetworkManager 来自主发起。

你执行的 `--simple-connect="apn=cmnet"` 就是在替手机系统补上它"自动拨号"那一步。

## 七、权限说明

当前用户不在 `dialout` 组时，无法直接读写 `/dev/ttyUSB*`。用 `mmcli`/`nmcli` 不受影响（root 服务）。若需自己用 AT 工具怼串口：

```bash
sudo usermod -aG dialout $USER   # 加组后重新登录生效
```

## 八、调试速查表

| 现象 | 原因 | 处理 |
|------|------|------|
| `sim-missing` | SIM 未插/接触不良/方向反 | 断电重插 nano-SIM |
| `AT+CSQ` 很低 | 未接天线/天线失效 | 检查 4G 天线 |
| 已注册但无 IP | APN 错误 | 核对运营商 APN |
| wwan0 一直 DOWN | 未建立数据连接 | 执行第③关拨号 |
| `print wwan0` 有 IP 但 ping 不通 | 路由/防火墙 | 检查默认路由与 DNS |

## 八·补、物联卡选型建议

### 物联卡是什么？
运营商专门给**机器设备**（非人用）办的 SIM 卡，面向车联网、摄像头、遥测等场景：
- **价格低**：流量单价远低于个人卡，适合长期、小流量、周期上传。
- **封闭性强**：通常走专用 APN（如 `cmiot`），仅数据，一般**不支持语音/短信**。

### 为什么插手机上"便宜但不好用"？
物联卡被设计为给机器用，插手机有硬伤：
- **限速严重**：套餐常限低速率，刷视频/下载明显卡顿。
- **优先级低**：网络拥堵时被运营商降速、排队。
- **不支持语音短信**：只能上网。
- **违规风险**：运营商**禁止物联卡用于手机**，可能被检测停机。
- **售后复杂**：第三方代理卡易有充值/跑路风险。

### 用在这个 4G 模块上效果如何？
**很好，是物联卡的主场**。模块用途（状态回传、遥测上报）与物联卡定位完全匹配：

| 需求 | 物联卡能否满足 |
|---|---|
| 长期 7x24 在线 | ✅ 设计目标 |
| 小流量、周期上传 | ✅ 最擅长，套餐便宜 |
| 只要数据、无需语音 | ✅ 正好 |
| 稳定接入网络 | ✅ 走专用 APN，专网更稳 |

### 选购建议
- **用途**：机上 4G 回传建议用物联卡，别拿个人卡长期跑（独立计费、不混流量、互不干扰）。
- **渠道**：优先运营商官方/正规渠道（移动 `cmiot`、电信、联通物联网业务），能实名、后台可查流量。
- **套餐**：按实际流量选购小流量套餐（如每月几百 MB ~ 几 GB）。
- **APN**：办卡时问清 APN（多为 `cmiot`），配置时填对即可（与 `cmnet` 同理）。

## 九、常见疑问（原理答疑）

**① 这些操作是第一次连接才需要，还是每次开机都要？**
- 底层"注册+拨号"**每次开机都会重新发生**：关机时基站会释放这块卡的一切临时资源（位置、数据会话、IP），下次开机需重新报到和申请通道，`wwan0` 的 IP 因此每次可能不同。
- 但**不必每次手动操作**：注册由 ModemManager 自动完成；拨号可配置成 NetworkManager **开机自动连接**，这样开机即自动联网，手动命令只在首次配置/学习时需要。

**② 用这张卡调试，会影响之后在手机里正常使用吗？**
- **不会**。注册、拨号、APN 都是网络侧会话和树莓派系统配置，ModemManager 不会改写 SIM 卡任何数据，插回手机完全正常。
- **同一时刻卡只能在一个设备里**：手机和模块不能同时用（网络侧同一号码同时只允许一个设备注册）。
- **会消耗这张卡的流量套餐**：模块联网会扣卡内流量，超量可能产生费用。建议后续向公司申请专用物联网卡给 4G 拓展板，套餐独立、计费清晰。

## 十一、本次调试过程总结（2026-08-07）

### 阶段 1：系统识别确认（顺利）
- USB 枚举 `1e0e:9001 SIMCOM_SIM7600G-H`，驱动 `qmi_wwan` + `option` 正常
- ModemManager 识别固件 `LE20B04SIM7600G-H-M2`，支持 2G/3G/4G，IMEI `864980080242496`
- **结论：模块/驱动/系统识别全部正常**

### 阶段 2：SIM 卡识别（首次卡点）
- 现象：`mmcli -m 5` 显示 `state: failed`、`failed reason: sim-missing`，两个卡槽均为 none
- 排查：确认为**卡没插**（物理层问题，软件无法解决）
- 处理：断电插入 nano-SIM 后，`mmcli -m 7` 显示 `state: registered`
- **经验：编号从 5 变 7，印证 ModemManager 编号不固定，需每次用 `mmcli -L` 确认**

### 阶段 3：网络注册（自动完成）
- `state: registered` 是 **ModemManager 后台自动触发**，无需手动操作
- 理解：注册=向运营商报到+鉴权；拨号=建立数据通道。手机把两者全自动化；模块则注册自动、拨号需手动

### 阶段 4：建立数据连接（核心卡点）
- 问题：`--simple-connect="apn=cmnet"` 显示 `successfully connected`，但 `wwan0` 仍 **DOWN、无 IP**，`ping` 报 `Network is unreachable`
- 根因：`--simple-connect` 只建立蜂窝会话，**不把 IP 配置到 wwan0 接口**；接口配置/拉起须交给 NetworkManager
- 解决：让 NetworkManager 接管
  ```bash
  sudo mmcli -m 7 --simple-disconnect
  sudo nmcli connection add type gsm ifname cdc-wdm0 con-name 4g apn cmnet
  sudo nmcli connection up 4g
  ```
- 结果：`wwan0` 拿到 IP `10.181.40.79/27`，`cdc-wdm0 gsm connected 4g`

### 阶段 5：联网验证（成功）
- `ping -I wwan0 8.8.8.8`：4/4 通，延迟约 60ms
- 公网出口 IP：`117.136.111.129`（中国移动 4G 段）
- 持久连接 `4g` 已配置，开机自动联网

### 关键结论与经验
| 项目 | 结论 |
|---|---|
| 上网 4 道关 | SIM识别 → 网络注册 → 数据连接 → 拿IP |
| 注册 | ModemManager 自动完成 |
| 拨号 | 需手动/NetworkManager 发起，需指定 APN |
| 手动拨号坑 | `--simple-connect` 不配接口 IP，须由 NM 接管 |
| APN | 个人卡用 `cmnet`；物联卡用 `cmiot` |
| SIM 编号 | 不固定，用 `mmcli -L` 确认 |
