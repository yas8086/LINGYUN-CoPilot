# 灵云01号 地面站对接协议（本地串口数传）

> 面向**地面站（Qt 桌面端）开发者**的协议对接说明。
> 地面站通过**串口数传链路**接收机载（树莓派5）下发的设备状态，本地实时显示。
> 本文档仅描述协议对接所需信息（物理链路、帧格式、字段定义），不含上位机 UI 实现细节。

---

## 1. 系统概述

```
机载 (树莓派5)                                   地面 (Qt 桌面端)
┌─────────────────────────────┐   串口数传     ┌────────────────────┐
│  BMS / MPPT / DCDC ──► CAN │  ──────────►  │  地面站 (解析 JSON 显示) │
│         │                  │  115200 8N1   └────────────────────┘
│    [ link_node ] ──────────┘  0xAA 0x55 + JSON + '\n'
└─────────────────────────────┘
```

- 机载 `link_node` 将 BMS / MPPT / DCDC / **LoRa 温度采集**等设备状态聚合为**单行 JSON**，加帧头帧尾后经串口周期下传。
- 地面站只需**打开串口、按帧解析 JSON** 即可获取设备实时状态。
- 本条链路为**本地操作通道**：低延迟、高频实时遥测；**不含**控制指令下发（当前阶段只做监控展示）。

---

## 2. 物理链路参数

| 项目 | 参数 |
|------|------|
| 串口设备（机载侧） | `/dev/ttyUSB0`（可配置 `link_node.serial_device`） |
| 波特率 | `115200` |
| 数据格式 | 8 数据位 / 1 停止位 / 无校验（8N1） |
| 流控 | 无（无硬件/软件流控） |
| 传输方向 | 机载 → 地面（单向下传） |
| 上报频率 | 默认 **5 Hz**（200 ms，可配置 `link_node.tx_rate_hz`） |

---

## 3. 帧格式

每帧由**帧头 + JSON + 帧尾**构成，机载循环下传：

```
帧结构:  0xAA 0x55 <JSON> \n
```

| 段 | 内容 | 说明 |
|----|------|------|
| 帧头 | `0xAA 0x55` | 2 字节固定帧头，用于定位帧起始 |
| 数据 | `<JSON>` | 单行 JSON，**不含换行符** |
| 帧尾 | `\n` (0x0A) | 换行，标识一帧结束 |

**解析要点：**
- 地面站以 `0xAA 0x55` 定位帧头，读取到 `\n` 结束一帧，中间字节即完整 JSON 文本。
- 相邻帧之间无额外分隔（帧尾 `\n` 即分隔符）。
- 每帧都是**独立完整**的 JSON 对象，解析失败时应丢弃本帧、继续找下一帧头，不影响后续接收。

---

## 4. JSON 数据模型

整体结构为单层对象，`t` 为时间戳，其余为各设备子对象。**离线设备不出现**在帧中：

```json
{
  "t": 1785928200.123,
  "bms":  { ... },
  "mppt": { ... },
  "dcdc": { ... },
  "lora": { "nodes": [ ... ] }
}
```

| 键 | 类型 | 说明 |
|----|------|------|
| `t` | number (double) | 机载打包时刻的 Unix 时间戳 [秒] |
| `bms` | object | 锂电池 BMS 状态（在线时存在） |
| `mppt` | object | MPPT 光伏控制器状态（在线时存在） |
| `dcdc` | object | DCDC 电源模块状态（在线时存在） |
| `lora` | object | LoRa 温度/压力采集（存在条件见下） |

> **注意 1**：`bms`/`mppt`/`dcdc` 在设备 `online=false` 或尚未收到数据时，其键**不会**出现在 JSON 中。帧内仅剩 `{"t":...}` 表示当前全部设备离线/未就绪。
>
> **注意 2**：`lora` 键的存在条件与上述不同——只要机载收到过一轮 LoRa 采样（`samples` 非空）就会出现；即使所有节点离线，`nodes` 仍会以空数组 `"lora":{"nodes":[]}` 形式出现。

## 5. 字段详细说明

### 5.1 BMS（`bms`）

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | CAN 链路是否在线（最近收到过有效帧） |
| `pack_v` | number | V | 电池包总压 |
| `pack_i` | number | A | 电池包总电流（**充电为正**） |
| `soc` | number | % | 荷电状态 (0–100) |
| `max_v` | number | V | 最高单体电压 |
| `min_v` | number | V | 最低单体电压 |
| `diff_v` | number | V | 单体压差 |
| `max_t` | number | ℃ | 最高单体温度 |
| `alarm` | int | - | 告警级别：`0` 正常 / `1` 故障 / `2` 严重 |

### 5.2 MPPT（`mppt`）

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | CAN 链路是否在线 |
| `pv_v` | number | V | 光伏电压 |
| `pv_p` | number | W | 光伏功率（计算值） |
| `batt_v` | number | V | 电池电压 |
| `charge_i` | number | A | 充电电流 |
| `today` | number | kWh | 日发电量 |
| `total` | number | kWh | 总发电量 |
| `fault` | int | - | 故障状态位（见厂家协议故障状态表，`0` 为无故障） |

### 5.3 DCDC（`dcdc`）

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | CAN 链路是否在线 |
| `in_v` | number | V | 输入电压（母线电压） |
| `out_v` | number | V | 输出电压 |
| `out_i` | number | A | 输出电流 |
| `out_p` | number | W | 输出功率（计算值） |
| `temp` | number | ℃ | 散热器温度 |
| `enabled` | bool | - | 输出是否开启 |
| `fault` | int | - | 故障状态字节（Bit 映射见厂家协议故障表，`0` 为无故障） |

### 5.4 LoRa（`lora`）

`lora` 为 LoRa 集中器采集的**温度/压力节点**列表，结构：

```json
"lora": {
  "nodes": [
    { "id": 1, "online": 1, "temp": 25.4, "pressure": 0,   "alarm": 0 },
    { "id": 2, "online": 1, "temp": 0,    "pressure": 101325, "alarm": 0 }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `nodes` | array | 在线节点数组；**离线节点不打包**（此处无 `online=0` 的项） |
| `id` | int | 节点 ID（自 `start_node_id` 递增） |
| `online` | int | 恒为 `1`（仅在线节点被打包） |
| `temp` | number (℃) | 温度值；**压力节点此值为 `0`** |
| `pressure` | number (Pa) | 压力值；**温度节点此值为 `0`** |
| `alarm` | int | 告警：`0` 正常 / `1` 超上限 / `-1` 超下限（**仅温度节点有效**，压力节点为 `0`） |

> 每个节点或为温度传感器、或为压力传感器（见 LoRaSample 的 `is_pressure`）。地面站可依据 `temp==0` / `pressure==0` 判断节点类型，或按节点 ID 约定识别。
> 空数组 `"nodes":[]` 表示本轮采样无在线节点。

## 7. 上报频率与时序

- **周期遥测**：默认每 200 ms（5 Hz）下发一帧（可配置 `link_node.tx_rate_hz`）。
- **离线处理**：设备超过 `monitor_node.link_timeout_s`（默认 3 s）未上报即判离线，随后其设备键从帧中消失（`lora` 除外，见第 4 节注意 2）。
- **字段精度**：浮点数值由机载格式化为**最多 3 位有效数字**（如 `367.2`、`0.0`、`12.8`），地面站按 `double` 解析即可。
- **串口自动重连（机载侧）**：机载检测到串口掉线后会按 `link_node.reconnect_ms`（默认 2 s）周期自动重连（数传电台/USB 插拔后自动恢复）。**地面站无需处理**，链路恢复后即自动恢复接收。

## 8. 协议对接清单（地面站侧）

1. **打开串口**：按第 2 节参数打开数传串口（波特率 115200，8N1）。
2. **帧定位**：缓存字节流，扫描 `0xAA 0x55` 定位帧头，至 `\n` 截取 JSON。
3. **JSON 解析**：将截取的 JSON 文本解析为对象；`t` 为时间戳，其余键按设备类型分发。
4. **容错**：JSON 解析失败或字段缺失时丢弃本帧；某设备键不存在即视为该设备离线。
5. **显示**：根据 `online` 与各字段刷新界面；`alarm`/`fault` 非 0 时提示告警。

---

## 9. 联调与测试

- **机载侧模拟**：可运行仓库 `tools/` 下的模拟器，在无实际硬件时生成数据流验证解析逻辑（例如以 `vcan0` 模拟 CAN 数据，启动 `link_node` 观察串口输出）。
- **机载实机**：启动全部设备监控后，串口即按帧持续下传（见 [01_设备监控架构](../../01_设备监控架构.md) 第 8 节 systemd 部署）。
- **验证工具**：可用 `minicom`/`cat` 查看串口原始数据，或用任意 JSON 工具校验帧内 JSON 合法性。

## 10. 与 4G 远程链路的区别（范围说明）

| 维度 | 本链路（串口数传） | 4G 上云（MQTT，见 [03_双链路与4G远程监控架构](../../03_双链路与4G远程监控架构.md)） |
|------|--------------------|-------------------|
| 范围 | 本地（地面站旁） | 异地/公网 |
| 协议 | 串口 + 自定义帧 | MQTT over TLS |
| 频率 | 5 Hz | 2 Hz（可配） |
| 方向 | 机载 → 地面 | 机载 → 公有云 |
| 覆盖设备 | BMS / MPPT / DCDC / LoRa | BMS / MPPT / DCDC / LoRa / 飞控 FC |

> 本文档**仅**面向本地串口数传链路；如需通过 4G 远程获取数据（含飞控状态），请参考 4G 上云链路文档。
