# 灵云01号 地面站对接协议（最新版）

> 面向**地面站（Qt 桌面端）开发者**的权威协议对接说明。
> 本文件依据机载端 **全部实现代码**（`airship_link` / `airship_cloud` / `airship_bms` / `airship_backup_bms` / `airship_mppt` / `airship_dcdc` / `airship_lora` / `airship_fc` / `airship_msgs` / `airship_monitor` / `airship_bringup`）逐字段核对生成，**字段、帧格式、精度规则、覆盖设备均与机载实际打包完全一致**。
>
> 地面站可通过三条通道获取机载数据：**串口数传**（本地/主推）、**数传网口 UDP**（本地/L33 冗余）与 **4G MQTT 上云**（远程监控）。各通道共用同一份 JSON 打包逻辑，字段定义与覆盖设备完全一致，仅传输方式与频率不同。

---

## 1. 系统概述

```
机载 (树莓派5)                                     地面
┌────────────────────────────────┐  串口数传 / 数传网口UDP    ┌───────────────────┐
│ BMS ──CAN                      │ ──────────────► │ 地面站 Qt 桌面端    │
│ 备用BMS ──串口(9600)           │  串口: /dev/airship_link    │ (解析 JSON 实时显示)│
│ MPPT ──CAN                     │  115200 8N1       ├───────────────────┤
│ DCDC ──CAN                     │  UDP: 数传网口     │ (可选) UDP 监听端   │
│ LoRa ──485(Modbus RTU)         │  AA 55 +JSON+\n   └───────────────────┘
│ FC ── 网口(MAVROS)             │
│        [ link_node ] ──────────┘
│        [ cloud_node ] ────────► 4G MQTT over TLS ─► EMQX 公有云(远程)
└────────────────────────────────┘
```

- **数传链路（`link_node`）**：将 BMS / 备用BMS / MPPT / DCDC / LoRa / 飞控 FC 聚合为单行 JSON，经串口与数传网口 UDP **双发下传**（见 2.1、6.5），供地面站实时显示。链路默认不含告警事件（仅状态快照）。
- **4G 链路（`cloud_node`）**：将相同设备聚合打包，经 MQTT over TLS 上报公有云（EMQX），用于远程监控。
- 两链路字段打包复用同一函数 `airship_link::pack_telemetry_json`，**覆盖设备与字段定义完全一致**；差异仅在传输方式（串口+UDP vs MQTT）。
- 当前阶段：**仅下传监控数据，不接收控制指令**（`safe_to_control` 机制见第 9 节，供后续控制接入）。

## 2. 链路参数速查

### 2.1 本地数传（地面站主对接链路，串口 + UDP 双发）

| 项目 | 参数 | 配置位置 |
|------|------|---------|
| 串口设备（机载侧） | `/dev/airship_link`（udev 固定链接；代码默认 `/dev/ttyUSB0`） | `link_node.serial_device` |
| 波特率 | `115200` | `link_node.baud_rate` |
| 数据格式 | 8 数据位 / 1 停止位 / 无校验（8N1），无流控 | - |
| UDP 目标（机载侧） | `192.168.10.200:20000`（地面站固定 IP 定向单播；高位端口避开数传 14550/14551/14552 映射段；联调可改广播 `192.168.10.255`；留空则仅串口） | `link_node.udp_host` / `udp_port` |
| 传输方向 | 机载 → 地面（双发，单向下传） | - |
| 上报频率 | 默认 **5 Hz**（200 ms） | `link_node.tx_rate_hz`（非法值≤0 回退 5.0） |
| 串口自动重连周期 | 2 s（机载侧自动，地面站无需处理） | `link_node.reconnect_ms` |

> 机载经 **串口 + UDP** 同时下传同一帧（冗余，一路故障不影响另一路）。地面站可选择任一路接入；UDP 下发时地面站在对应端口监听即可，帧格式与串口一致（`0xAA 0x55 [JSON]\n`）。

### 2.2 4G MQTT 上云（远程监控链路）

| 项目 | 参数 | 配置位置 |
|------|------|---------|
| Broker | EMQX Cloud Serverless（Europe / AWS eu-central-1） | `cloud_node.mqtt_host` |
| 端口 / 协议 | `8883` / **MQTT over TLS（必须）** | `cloud_node.mqtt_port` / `mqtt_tls_enable` |
| 遥测 Topic | `lingyun01/telemetry` | `cloud_node.mqtt_topic` |
| 认证 | 用户名 + 密码（密码经 `MQTT_PASSWORD` 环境变量注入，不落 cmdline） | `mqtt_username` / `mqtt_password` |
| TLS 证书 | 默认系统 CA `/etc/ssl/certs`（公签证书） | `mqtt_tls_ca_cert` / `mqtt_tls_insecure` |
| 上报频率 | 默认 **2 Hz**（可配） | `cloud_node.tx_rate_hz`（非法值≤0 回退 2.0） |

> 4G 仅**上行上报**，不接收任何控制指令。

## 3. 数传帧格式（串口 / UDP 一致）

每帧由**帧头 + JSON + 帧尾**构成，机载循环下传；该帧格式**同时用于串口与数传网口 UDP 通道**（软链路 UDP 中 `\n` 保留，便于与串口用同一解析逻辑）：

```
帧结构:  0xAA 0x55 <JSON> \n
```

| 段 | 内容 | 说明 |
|----|------|------|
| 帧头 | `0xAA 0x55` | 2 字节固定帧头，用于定位帧起始 |
| 数据 | `<JSON>` | 单行 JSON，**不含换行符** |
| 帧尾 | `\n` (0x0A) | 换行，标识一帧结束 |

**解析要点：**
- 地面站以 `0xAA 0x55` 定位帧头，读至 `\n` 结束一帧，中间字节即完整 JSON 文本。
- 相邻帧间无额外分隔（帧尾 `\n` 即分隔符）。
- 每帧独立完整；解析失败丢弃本帧、继续找下一帧头，不影响后续接收。
- 机载**写入失败**时主动关闭串口并自动重连（第 8 节），地面站对短暂数据中断做容错处理、可标记"链路离线"。

## 4. JSON 数据模型

整体为单层对象，`t` 为时间戳，其余为各设备子对象。**离线设备不出现**在帧中：

```json
{
  "t": 1785928200.123,
  "bms":    { ... },
  "backup": { ... },
  "mppt":   { ... },
  "dcdc":   { ... },
  "fc":     { ... },
  "lora":   { "nodes": [ ... ] }
}
```

数传与 4G 两链路的完整顶层键（按打包顺序）：`t` → `bms` → `backup` → `mppt` → `dcdc` → `fc` → `lora`。
> **与旧文档的差异**：`fc`（飞控）现由 `link_node` 一并订阅并打包，**数传链路也包含飞控数据**，两链路覆盖完全一致。

| 键 | 类型 | 说明 |
|----|------|------|
| `t` | number (double) | 机载打包时刻 Unix 时间戳 [秒]（`%.3f`，3 位小数） |
| `bms` | object | 主电源锂电池 BMS（在线时存在） |
| `backup` | object | 12S 备用电源 BMS（在线时存在） |
| `mppt` | object | MPPT 光伏控制器（在线时存在） |
| `dcdc` | object | DCDC 电源模块（在线时存在） |
| `fc` | object | 飞控状态（在线时存在） |
| `lora` | object | LoRa 温度/压力采集（存在条件见下） |

> **注意 1（存在条件）**：`bms`/`backup`/`mppt`/`dcdc`/`fc` 在设备 `online=false` 或尚未收到数据时，其键**不会**出现。帧内仅剩 `{"t":...}` 表示这些设备全部离线/未就绪。
>
> **注意 2（lora 例外）**：`lora` 键只要机载收到过一轮 LoRa 采样（`samples` 非空）即出现；节点全离线时为 `"lora":{"nodes":[]}` 空数组。

## 5. 字段详细说明

> **类型**：`number`=JSON 数值；`bool`=`true`/`false`；`int`=十进制整数。
> **特殊值**：机载对非有限浮点（NaN/Inf）统一输出 JSON `null`，地面站须接受 `null` 并视为无效值，勿强转 0。

### 5.1 BMS（`bms`）— 主电源电池（102 串三元锂）

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | CAN 链路是否在线 |
| `pack_v` | number | V | 电池包总压 |
| `pack_i` | number | A | 电池包总电流（**充电为正**） |
| `soc` | number | % | 荷电状态 (0–100) |
| `rsoc` | number | % | 真实 SOC（`real_soc`） |
| `max_v` | number | V | 最高单体电压 |
| `min_v` | number | V | 最低单体电压 |
| `diff_v` | number | V | 单体压差 |
| `max_t` | number | ℃ | 最高单体温度 |
| `min_t` | number | ℃ | 最低单体温度 |
| `avg_t` | number | ℃ | 平均单体温度 |
| `diff_t` | number | ℃ | 单体温差 |
| `riso_p` | int | kΩ | 正极绝缘电阻 |
| `riso_n` | int | kΩ | 负极绝缘电阻 |
| `alarm` | int | - | 告警级别：`0` 正常 / `1` 故障 / `2` 严重 |
| `soh` | number | % | 健康状态 |
| `fault1` / `fault2` / `fault3` | int | - | 一级/二级/三级故障/告警字（32 位，按位解析；`fault1` 含系统故障位 bit0 + 一级报警 bit16 等） |

### 5.2 备用电源 BMS（`backup`）— 12S 备用电池

12S 备用电源（北辰串口协议 V1.4），经串口轮询解析。

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | 串口链路是否在线 |
| `pack_v` | number | V | 电池包总压 |
| `pack_i` | number | A | 电池包总电流（充电为正） |
| `soc` | number | % | 荷电状态 (0–100) |
| `soh` | number | % | 健康状态 (0–100) |
| `max_v` | number | V | 最高单体电压 |
| `min_v` | number | V | 最低单体电压 |
| `diff_v` | number | V | 单体压差 |
| `max_t` | number | ℃ | 最高单体温度 |
| `min_t` | number | ℃ | 最低单体温度 |
| `avg_t` | number | ℃ | 平均单体温度 |
| `diff_t` | number | ℃ | 单体温差 |
| `alarm` | int | - | 告警标志位（`alarm_word`，32 位） |
| `protect` | int | - | 保护标志位（`protect_word`，32 位） |
| `fault` | int | - | 故障标志位（`fault_word`：Bit0 放MOS失效/Bit1 充MOS失效/Bit4 短路/Bit30 保险丝/Bit31 掉线） |
| `sys` | int | - | 系统状态字（`system_word`：Bit0 放电MOS/Bit1 充电MOS/Bit5 充电器接入/Bit6 负载连接/Bit9-10 工作状态） |

> `alarm`/`protect`/`fault`/`sys` 均为 32 位无符号整数，按位与判定（`(fault & 0x1) != 0` 表示放MOS失效等）。

### 5.5 飞控 FC（`fc`）— 数传与 4G 均含

> `fc` 由 `link_node` 与 `cloud_node` 均订阅 `/fc/status` 并打包，**两条链路都包含飞控数据**。字段取自 `fc_monitor` 聚合的 `FlightStatus`，打包子集如下：

| 字段 | 类型 | 单位 | 说明 |
|------|------|------|------|
| `online` | bool | - | MAVROS 连接 + 心跳看门狗（`fc_timeout_s`=2s） |
| `roll` | number | deg | 横滚角 |
| `pitch` | number | deg | 俯仰角 |
| `yaw` | number | deg | 偏航角 |
| `lat` | number (6位) | deg | 纬度 |
| `lon` | number (6位) | deg | 经度 |
| `alt` | number | m | 相对起飞点高度（`alt_rel`） |
| `vx` | number | m/s | 东向速度 (ENU) |
| `vy` | number | m/s | 北向速度 (ENU) |
| `vz` | number | m/s | 天向速度 (ENU) |
| `mode` | string | - | 当前飞行模式（已做 JSON 转义） |
| `armed` | bool | - | 是否解锁 |
| `hdg` | number | deg | 航向角（`heading_deg`，来自 VfrHud compass_hdg，0~360） |
| `airspd` | number | m/s | 空速（来自 VfrHud.airspeed，安装版无 Airspeed.msg，与 tas 同源） |
| `tas` | number | m/s | 真空速（与 airspd 同源当前；升级 mavros_msgs 后可分离 IAS/TAS） |
| `gs` | number | m/s | 地速 |
| `climb` | number | m/s | 垂直爬升率 |
| `thr` | number | % | 油门（0~100） |
| `batt_v` | number | V | 电池电压 |
| `batt_pct` | number | - | 剩余电量（`battery_remaining`，0~1） |
| `ekf` | object | - | EKF 估计器健康标志：`const_pos`（位置锁定，GPS 失效）、`glitch`（GPS 毛刺）、`accel_err`（加速度计错误），均为 bool |
| `gps` | object | - | GPS 原始数据：`fix`（0=无 1=NO_FIX 2=2D 3=3D 4=DGPS 5/6=RTK）、`sat`（卫星数，255=未知）、`eph`（水平精度 HDOP）、`epv`（垂直精度 VDOP） |
| `esc` | object | - | 电机 ESC 遥测（DroneCAN/CAN 电调回传时 `n`>0；PWM 供电时 `n`=0）：`n`=有遥测电调数、`rpm`/`v`/`i`/`tmp` 各为定长数组 [10] |

`ekf`/`gps`/`esc` 完整结构示例：

```json
"ekf": {"const_pos":false,"glitch":false,"accel_err":false},
"gps": {"fix":6,"sat":18,"eph":50,"epv":80},
"esc": {"n":10,"rpm":[3200,...],"v":[48.1,...],"i":[12.5,...],"tmp":[35,...]}
```

> 注：`FlightStatus` 中另有 `alt_amsl`/`roll_rate`/`pitch_rate`/`yaw_rate`/`motor_outputs`/`landed_state`/`battery_current` 等字段，**当前未进入 JSON 打包**，如需展示请另行扩展打包逻辑。

### 5.6 LoRa（`lora`）— 温度/压力节点

```json
"lora": {
  "nodes": [
    { "id": 1, "online": 1, "temp": 25.4,   "pressure": 0,       "alarm": 0 },
    { "id": 2, "online": 1, "temp": 0,      "pressure": 101325,  "alarm": 0 }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `nodes` | array | 在线节点数组；**离线节点不打包**（数组内无 `online=0` 项） |
| `id` | int | 节点 ID |
| `online` | int | 恒为 `1`（仅在线节点被打包） |
| `temp` | number (℃) | 温度值；**压力节点此值为 `0`** |
| `pressure` | number (Pa) | 压力值（6 位小数）；**温度节点此值为 `0`** |
| `alarm` | int | `0` 正常 / `1` 超上限 / `-1` 超下限（仅温度节点有效） |

> 节点或为温度、或为压力传感器。可依 `temp==0`/`pressure==0` 判断类型，或按节点 ID 约定识别。空数组 `"nodes":[]` 表示本轮无在线节点。

## 6. 完整示例帧（数传链路）

原始字节（十六进制示意）：

```
AA 55 7B 22 74 22 3A 31 37 38 35 ... 7D 0A
│   │  └─────────── JSON ──────────┘  │
└───┘                                 └── 帧尾 \n
```

解析后的 JSON（字段齐全）：

```json
{
  "t": 1785928200.123,
  "bms": {
```

## 7. 精度、类型与特殊值规则（重要）

地面站解析须遵循机载序列化规则，避免类型/精度误判：

| 项 | 规则 |
|----|------|
| 浮点字段（float32） | `%.4g`，**最多 4 位有效数字**（如 `367.2`、`0.0`、`600.0`），按 `double` 解析 |
| 高精度字段（double） | `lat`/`lon`/LoRa `pressure` 用 `%.6f` 固定 6 位小数（如 `31.230400`、`101325.000000`） |
| 时间戳 `t` | `%.3f`，3 位小数秒 |
| 非有限值 | NaN/Inf → JSON `null`；接受 `null` 视为无效值，勿强转 0 误导显示 |
| 字符串 | 机载已做 JSON 转义（`"`→`\"`、`\`→`\\`、换行/回车/制表→`\n`/`\r`/`\t`、其它控制符→`\uXXXX`）；标准 JSON 解析自动还原 |
| 整数/位标志 | `riso_p`/`riso_n`、`alarm`/`protect`/`fault`/`sys`/`fault1/2/3` 输出十进制整数，按位解析 |
| 定长数组 | `fc.esc.rpm/v/i/tmp` 各为长度 10 的数值数组；`esc.n` 为有效元素数，索引 < `n` 可信，`n`~10 之间为占位（当前实现全数组输出，电调数不足时尾部为 0） |

## 8. 上报频率与时序

- **数传**：默认 200 ms（5 Hz）一帧；设备离线判定超时 `monitor_node.link_timeout_s`=3 s。串口与 UDP 同频双发。
- **4G**：默认 500 ms（2 Hz）一帧。
- **离线处理**：`bms`/`backup`/`mppt`/`dcdc`/`fc` 超时未上报即判离线，键从帧中消失（`lora` 除外，见第 4 节注意 2）。
- **机载串口自动重连**：检测到未打开或写入失败时按 `reconnect_ms`（2 s）周期自动重连，恢复后自动下传；地面站无需处理，数据中断期间标记"链路离线"、恢复后自动刷新。

## 9. 安全状态与告警（说明性）

- **安全状态**：`airship_safety` 发布 `/safety_status`（`SafetyStatus`：`safe_to_control`、`dcdc_ok`、`battery_ok`、`backup_battery_ok`、`flight_armed`、`reason`）。**当前未进入数传/4G JSON 打包**，供后续接入 DCDC/飞控控制时使用。地面站如需展示安全状态，须另行接入该消息。
- **设备告警**：`airship_monitor` 发布 `/monitor/device_alert`（`DeviceAlert`，设备类型：BMS=1/MPPT=2/DCDC=3/LoRa=4/备用BMS=5；级别 INFO=0/WARNING=1/CRITICAL=2）。**当前也未进入 JSON 打包**——数传 JSON 仅含状态快照，不含告警事件流。
- 飞控告警：`airship_fc` 发布 `/fc/alert`（`FcAlert`，LEVEL_INFO/WARNING/CRITICAL/EMERGENCY），同样未进入 JSON。
- 地面站若需**事件/告警推送**，当前需另行设计（例如由地面站对 JSON 中 `alarm`/`fault`/`online` 字段做本地阈值与状态跳变判断），或扩展机载打包逻辑。

## 10. 协议对接清单（地面站侧）

1. **接入数传**（任选其一或并行）：
   - **串口**：按 2.1 参数（115200，8N1，无流控）；
   - **UDP**：绑定本地 `udp_port`（默认 20000）监听数传网口下发的帧。
2. **帧定位**：缓存字节流，扫描 `0xAA 0x55` 定帧头，至 `\n` 截取 JSON（串口/UDP 同格式）。
3. **JSON 解析**：解析对象；`t` 为时间戳，其余键分发到 BMS/备用BMS/MPPT/DCDC/FC/LoRa 结构。
4. **容错**：
   - JSON 解析失败 → 丢弃本帧；
   - 设备键不存在 → 视为离线；
   - 字段值 `null`（NaN/Inf）→ 按无效值处理；
   - 位标志按位与判定。
5. **显示**：按 `online` 与各字段刷新界面；`alarm`/`fault`/`fault1` 等非 0 提示告警。
6. **LoRa 类型识别**：`temp==0`/`pressure==0` 区分温度/压力节点。
7. **飞控扩展字段**：`fc.ekf`/`fc.gps`/`fc.esc` 为子对象，注意 `esc.n`=0 表示无电机遥测（PWM 电调）。
8. **（可选）4G 远程**：订阅 `lingyun01/telemetry`，JSON 结构与数传一致，TLS 8883。

## 11. 数传与 4G 链路的区别（范围说明）

| 维度 | 数传（本地 `link_node`） | 4G（远程 `cloud_node`） |
|------|--------------------|-------------------|
| 范围 | 本地（地面站旁） | 异地/公网 |
| 协议 | 串口 + UDP，自定义帧（AA 55 JSON \n） | MQTT over TLS（8883） |
| 频率 | 5 Hz（串口/UDP 双发） | 2 Hz（可配） |
| 方向 | 机载 → 地面 | 机载 → 公有云 |
| 覆盖设备 | BMS / 备用BMS / MPPT / DCDC / **FC** / LoRa | BMS / 备用BMS / MPPT / DCDC / **FC** / LoRa |
| 飞控 FC | **含**（`link_node` 订阅 `/fc/status` 打包） | **含**（`fc` 字段） |
| 告警/安全 | **均不含**（仅状态快照） | **均不含**（仅状态快照） |

> 两链路字段打包复用同一 `pack_telemetry_json`，**覆盖设备与字段定义完全一致**；差异仅在传输方式（串口+UDP vs MQTT）与频率。数传链路已内置飞控数据，无需额外订阅。
