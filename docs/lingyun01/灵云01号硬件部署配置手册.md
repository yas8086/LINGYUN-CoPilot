# 灵云01号伴飞电脑 硬件部署配置手册

> 适用范围：
> - SBC：树莓派 5（8GB / RAM 版推荐）
> - OS：Ubuntu 24.04 LTS 64-bit（ARM64）
> - 扩展板组合（同时叠装）：
>   1. 树莓派5（本体）
>   2. Waveshare Pi5 Connector Adapter (B) —— 24V DC 转树莓派 USB-C 供电
>   3. Waveshare RS232-RS485-CAN-Board 工业隔离接口板 —— 直插 40pin GPIO
>   4. Mcuzone MPUUART —— PCIe 转 USB 串口扩展板（接底部 PCIe FPC）
>   5. Waveshare 4G 扩展板（SIM7600） —— USB 口直插
> - 外设清单：
>   - 飞控 CUAV X25 EVO（ETH → 树莓派 RJ45）
>   - 温度压力集中器（RS485）
>   - 102S 主电池 BMS（CAN 250kbps）
>   - MPPT（CAN 250kbps）
>   - DCDC（CAN 250kbps）
>   - 12S 备用电源（RS485）
>   - 数传 L33 + L39（TTL 模式，冗余）
>   - 4G 模块 SIM7600（USB）

## 一、完整硬件接口分配表

| 外设 | 通讯类型 | 物理接线到树莓派 | Linux 原生设备 | 稳定符号链接 /dev/airship_* | 波特率 |
|---|---|---|---|---|---|
| **飞控 X25 EVO** | ETH | RJ45 网口 | eth0 | — | 1Gbps / UDP |
| **温度压力集中器** | RS485（隔离） | MPUUART RS485_1 | ttyACM0 (接口0) | `airship_485_concentrator` | 9600 |
| **12S 备用电源 BMS** | RS485（隔离） | MPUUART RS485_2 | ttyACM1 (接口1) | `airship_backup_bms` | 待定 |
| **数传 L33** | TTL UART | MPUUART TTL_1 | ttyACM2 (接口2) | `airship_radio_l33` | 待定（建议 115200） |
| **数传 L39** | TTL UART | MPUUART TTL_2 | ttyACM3 (接口3) | `airship_radio_l39` | 待定（建议 115200） |
| **102S 主 BMS / MPPT / DCDC** | CAN 2.0（共线） | 微雪工业板 MCP2515 | can0 | `airship_can_bms` | 250 kbps |
| **CAN FD 预留** | CAN FD | 微雪工业板 MCP2518FD | can1 | `airship_can_fd` | 500k / 2M |
| **调试 RS232（留用）** | RS232 | 微雪工业板 RS232 | ttyAMA0 (GPIO14/15) | `airship_debug_rs232` | 115200 |
| **调试 UART（留用）** | TTL | 板载 UART2 (GPIO4/5) | ttyAMA2 | `airship_debug_uart` | 115200 |
| **LoRa 485（旧版 FTDI 兼容）** | USB-RS485 | USB → FTDI | ttyUSB* | `airship_485` (旧规则保留) | 9600 |
| **4G SIM7600 AT口 0~4** | USB 多口 | USB → SimTech | ttyUSB*（按接口号） | `airship_4g_at0..4` | 115200 |

> **设计说明**：
> - CAN 总线上三个设备（BMS/MPPT/DCDC）波特率**必须一致**，本手册统一 250kbps；若有设备不一致，需接 can1 或单独加 USB-CAN 适配器
> - 两个数传 L33/L39 走 MPUUART 的 TTL 模式，若机载布线距离长，可改接微雪工业板的 RS232，或切换数传 422 半双工再接 RS485
> - 温度压力集中器 + 12S 备用电源走 MPUUART 的两路**隔离 RS485**，抗干扰更可靠

## 二、cmdline.txt：释放串口控制台

```bash
sudo nano /boot/firmware/cmdline.txt
```

删除下列片段（把系统控制台只留给 HDMI）：

```diff
- console=serial0,115200
- console=ttyAMA10,115200
```

确保开头包含 `console=tty1`。示例：

```
console=tty1 root=PARTUUID=xxxxxx rootfstype=ext4 fsck.repair=yes rootwait quiet splash
```

**同步禁用 getty 服务**（避免抢占 ttyAMA0 RS232 口）：

```bash
sudo systemctl stop    serial-getty@ttyAMA0.service
sudo systemctl disable serial-getty@ttyAMA0.service
sudo systemctl mask    serial-getty@ttyAMA0.service   # 可选，彻底禁用
```

## 三、/boot/firmware/config.txt（Ubuntu 24.04）

文件位置：见 [tools/rpi5_ubuntu2404_config.txt](file:///home/lingyun01/LINGYUN-CoPilot/tools/rpi5_ubuntu2404_config.txt)

**关键段解析**：

| 配置项 | 作用 |
|---|---|
| `enable_uart=1` | 启用 GPIO14/15 的 UART 硬件（给 RS232 用） |
| `dtparam=cooling_fan=on` + fan_tempX | 板载官方主动散热器四级温控曲线（Ubuntu 默认不开） |
| `dtparam=pcie=on` | 打开底部 PCIe，给 MPUUART 板识别 |
| `dtoverlay=uart2` | 启用 GPIO4/5 作备用调试 UART（ttyAMA2） |
| `dtparam=spi=on` | 开 SPI0（微雪工业板用） |
| `dtoverlay=sc16IS752-spi0,int_pin=25` | SC16IS752 双 RS485 |
| `dtoverlay=mcp2515-can1,oscillator=16000000,interrupt=24` | MCP2515 CAN 2.0（BMS/MPPT/DCDC） |
| `dtoverlay=mcp251xfd,spi0-2,interrupt=23` | MCP2518FD CAN FD |

⚠️ **SPI 片选/中断引脚修正**：
微雪工业板实际 CE/IRQ 脚请以它官方 wiki 的跳线/默认值为准。上面值（int_pin=25/24/23、spimaxfrequency 等）是通用参考，
**务必在目标板上对照 Waveshare RS232-RS485-CAN-Board 官方配置文件确认，否则 CAN/485 会无数据**。

**安装步骤**：

```bash
# 先备份原始 config.txt
sudo cp /boot/firmware/config.txt /boot/firmware/config.txt.bak.$(date +%Y%m%d)

# 用项目里的配置覆盖（或手动复制 [all] 段）
sudo cp /home/lingyun01/LINGYUN-CoPilot/tools/rpi5_ubuntu2404_config.txt /boot/firmware/config.txt

# 重启生效
sudo reboot
```

## 五、udev 稳定符号链接

分两份规则（70/71，顺序加载）：

| 规则文件 | 覆盖设备 |
|---|---|
| [tools/70-airship-usb.rules](file:///home/lingyun01/LINGYUN-CoPilot/tools/70-airship-usb.rules) | USB 直插：旧 FTDI 485、SIM7600 4G AT 口 |
| [tools/71-airship-extboards.rules](file:///home/lingyun01/LINGYUN-CoPilot/tools/71-airship-extboards.rules) | PCIe MPUUART (ttyACM*)、SPI 扩展 (ttySC*)、板载 UART、CAN 接口 |

**安装**：

```bash
sudo cp tools/70-airship-usb.rules /etc/udev/rules.d/70-airship-usb.rules
sudo cp tools/71-airship-extboards.rules /etc/udev/rules.d/71-airship-extboards.rules
sudo udevadm control --reload-rules
sudo udevadm trigger --subsystem-match=tty --action=add
sudo udevadm trigger --subsystem-match=net --action=add
```

**验证**：

```bash
echo "=== 串口符号链接 ==="
ls -l /dev/airship_* 2>/dev/null || echo "未生成（检查规则中 VID/PID/接口号）"

echo "=== CAN 网络接口 ==="
ip -br link show can0 can1
```

> 如果 MPUUART 的 4 路 ttyACM 的 `ID_USB_INTERFACE_NUM` 与预期不符（00..03 顺序变了），用：
> ```bash
> udevadm info -a /dev/ttyACM0 | grep INTERFACE_NUM
> ```
> 实际采集后再更新 71 号规则中的 `ENV{ID_USB_INTERFACE_NUM}` 值。

## 六、CAN 接口 systemd-networkd 开机自启

两份 `.network` 文件，由 systemd-networkd 启动 can0/can1 并设置波特率：

| 文件名 | 说明 |
|---|---|
| [tools/80-airship-can.network](file:///home/lingyun01/LINGYUN-CoPilot/tools/80-airship-can.network) | can0 @ 250kbps（BMS/MPPT/DCDC 共线） |
| [tools/81-airship-canfd.network](file:///home/lingyun01/LINGYUN-CoPilot/tools/81-airship-canfd.network) | can1 @ 500k/2M CAN FD（预留） |

**安装**：

```bash
sudo systemctl enable --now systemd-networkd

sudo cp tools/80-airship-can.network  /etc/systemd/network/80-airship-can.network
sudo cp tools/81-airship-canfd.network /etc/systemd/network/81-airship-canfd.network

sudo systemctl restart systemd-networkd
```

**验证**：

```bash
networkctl status can0
networkctl status can1

ip -d link show can0
ip -d link show can1
```

> 注意：`airship-device-monitor.service` 的 `ExecStartPre` 仍保留 `ip link set can0 up...` 兜底逻辑，即使 networkd 异常仍能拉起 CAN，二者不冲突。

## 七、4G 模块拨号（SIM7600，USB）

Ubuntu 24.04 推荐用 **ModemManager + NetworkManager（或 systemd-networkd）**：

```bash
sudo apt install -y usb-modeswitch modemmanager network-manager
sudo systemctl enable --now ModemManager
sudo systemctl enable --now NetworkManager
```

然后配置 APN：

```bash
sudo mmcli -L                          # 列出 modem，拿到 /0
sudo mmcli -m 0 --simple-status        # 看 SIM 状态
sudo nmcli c add type gsm ifname '*' con-name 'airship-4g' apn 'cmnet'
# ⚠️ APN 按 SIM 卡运营商修改（移动 cmnet / 联通 3gnet / 电信 ctnet）
sudo nmcli c up airship-4g
```

4G 的 5 个 AT 口已由 `70-airship-usb.rules` 绑定到 `/dev/airship_4g_at0..4`，若仅做 QMI/PPP 拨号，符号链接可不用，但便于手动发 AT 指令调试。

## 八、WiFi 多连接配置（NetworkManager / nmcli）

树莓派通过 wlan0 连接多个 WiFi（手机热点 / 公司 WiFi / 各场地热点），
由 **NetworkManager 管理并自动切换**：热点开着 → 优先连热点；热点没开 → 自动降级连公司 WiFi。
与 eth0 的 netplan 静态 IP（连飞控 10.41.10.100/24）并存，互不影响。

### 8.1 WiFi 管理脚本

仓库提供 [tools/Wifi/airship_wifi.sh](file:///home/lingyun01/LINGYUN-CoPilot/tools/Wifi/airship_wifi.sh)（配套说明见 [tools/Wifi/README.md](file:///home/lingyun01/LINGYUN-CoPilot/tools/Wifi/README.md)），三个子命令：

| 子命令 | 作用 | 示例 |
|---|---|---|
| `list` | 打印所有已保存 WiFi（SSID/密码状态/优先级/当前状态） | `sudo bash airship_wifi.sh list` |
| `add <SSID> [密码] [优先级]` | 新增或更新一个 WiFi（已存在只更新，不重连） | `sudo bash airship_wifi.sh add "于永强的iPhone" "qwertyuiop" 100` |
| `rm <SSID>` | 删除一个 WiFi 连接 | `sudo bash airship_wifi.sh rm "公司WiFi"` |

**优先级说明：**
- `connection.autoconnect-priority` 数值越大越优先，默认 0；多个 WiFi 都可用时先连优先级最高的，连不上自动降级。
- 建议：手机热点 100、公司 WiFi 50、各场地热点依次递减。
- 修改已有 WiFi 的优先级/密码：重新 `add` 即可覆盖，不会打断当前连接。

**典型流程：**
```bash
# 1. 先查看当前已保存的 WiFi 及优先级，确定要调整的目标
sudo bash airship_wifi.sh list

# 2. 按需新增 / 调整（传参方式：账号 密码 优先级）
sudo bash airship_wifi.sh add "于永强的iPhone" "qwertyuiop" 100
sudo bash airship_wifi.sh add "公司WiFi" "公司密码" 50

# 3. 再 list 确认
sudo bash airship_wifi.sh list
```

### 8.2 现场临时连新热点（不保存为长期连接）

```bash
nmcli device wifi connect "新场地热点" password "密码"   # 自动保存并立即连接
```

### 8.3 验证

```bash
nmcli connection show          # 已保存的 WiFi 及优先级
nmcli device status            # wlan0 当前连接的 WiFi
ip -br addr show wlan0
```

### 8.4 注意事项

- **手机热点需关闭「AP 隔离 / 设备隔离」**，否则同一热点下树莓派与电脑互相访问不到（最常见问题）。
- wlan0 走 DHCP，每次连热点 IP 会变；建议用 mDNS 主机名连接 `ssh <用户>@<主机名>.local`（需 avahi-daemon 运行）。
- 若 `/etc/netplan/` 下存在旧的 wlan0 配置（如 `99-airship-wifi-hotspot.yaml`），
  **手动删除**并 `netplan apply`，只保留 eth0 的 `90-NM-*.yaml`，避免 netplan 与 NetworkManager 对 wlan0 双重管理。

## 十一、完整部署验证清单（机载装机前必跑）

按顺序执行，每一步都 PASS 再装机：

```bash
# === 1. 系统基础 ===

# === 2. 风扇（升温 1 分钟看是否转）===
sudo apt install -y stress-ng
(stress-ng --cpu 4 --vm 2 --vm-bytes 512M --timeout 60) &
watch -n1 vcgencmd measure_temp             # 温度到 45°C+ 风扇应启动

# === 3. PCIe + MPUUART 串口板 ===
lspci                                       # 看是否出现 PCIe→USB HUB
ls -l /dev/ttyACM*                          # 期望 4 个 (ACM0..ACM3)
ls -l /dev/airship_485_concentrator
ls -l /dev/airship_backup_bms
ls -l /dev/airship_radio_l33
ls -l /dev/airship_radio_l39

# === 4. SPI 扩展板（微雪）===
ls -l /dev/ttySC*                           # 期望 ttySC0 / ttySC1
ls -l /dev/airship_485_concentrator_ws
ls -l /dev/airship_backup_bms_ws

# === 5. CAN ===
ip -br link show can0 can1                  # 期望 can0 UP / LOWER_UP
ls -l /dev/airship_can_bms
candump can0                                # 接 BMS/MPPT/DCDC 后应该有报文

# === 6. 4G ===
mmcli -L                                    # 应识别到 SIM7600

# === 7. WiFi（nmcli 多连接）===

# === 8. 飞控 ETH ===

# 启动 ROS2 后：ros2 topic echo /mavros/state   确认飞控连接状态

# === 9. 供电稳定性（满载 10 分钟）===
(stress-ng --cpu 4 --vm 2 --vm-bytes 1G --timeout 600) &

# 无 under-voltage / hwmon reset 等告警才算 PASS

sudo reboot
# 启动后：
systemctl is-active airship-device-monitor     # active
systemctl is-active airship-dcdc-hold          # active
networkctl status can0                         # routable/configured
```

## 十二、常见问题 & 排查手册

### Q1. 风扇不转？
- 看第三节温控曲线，低于 45°C 不转是正常；跑 stress-ng 升温验证
- `dmesg | grep -i fan`，若有 cooling_fan 相关错误 → 检查 config.txt 的 `cooling_fan=on`
- `echo 255 | sudo tee /sys/devices/platform/cooling_fan/hwmon/hwmon*/pwm1` 强制全速

### Q2. ttyACM0~3 不出现？
- `lspci` 确认 PCIe 设备存在；`lsusb` 应有 PCIe→USB HUB
- `dmesg | grep -i cdc_acm` 查看 ACM 绑定日志

### Q3. can0 接口不存在？
- `lsmod | grep mcp251x`，无则 `sudo modprobe mcp251x`
- `dmesg | grep mcp` 查注册失败日志，常是 **IRQ 脚配错** → 修正 config.txt 中 `interrupt=`

### Q4. udev 符号链接不出现？
- `udevadm test $(udevadm info -q path -n /dev/ttyACM0) 2>&1 | grep -i symlink`
- 重点查 `ID_USB_INTERFACE_NUM` 实际值

### Q5. 数传 TTL 波特率/接线？
- L33/L39 推荐 115200 8N1，接 MPUUART 的 TTL 口时注意 GND 必须共地
- 若数传切换到 RS232 模式，改接微雪工业板 ttyAMA0（`airship_debug_rs232` 映射）

### Q6. 供电不足反复重启？
- 24V 入线 → 微雪工业板端子：确认工业板 DCDC 5V 输出 ≥5A
- 若不够 → 树莓派 USB-C 口用独立 5V/5A 供电（方案 A），不依赖 Adapter B
