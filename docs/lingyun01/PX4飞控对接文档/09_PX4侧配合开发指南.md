## 0. 背景与目标（1 分钟读完）

飞艇有 4 个空气囊（左副囊/左主囊/右主囊/右副囊），每个囊装有一个 LoRa 压差传感器（相对大气压的有符号压差，单位 Pa）。树莓派采集后经 uXRCE-DDS 发到飞控，飞控控制逻辑消费该数据。

**整体链路（树莓派侧全部就绪）：**

```
[LoRa 压力传感器 x4]           [树莓派 10.41.10.100]                [PX4 飞控 10.41.10.2]
 6=左副囊  13=左主囊  ──485──▶ lora_node                            uxrce_dds_client ← 你要配的
 14=右主囊 15=右副囊           └─ bladder_bridge_node                └─ uORB: airship_bladder_pressure
                                  └─ ROS2 话题 /fmu/in/airship_bladder_pressure    ← 你的控制模块订阅
                                  └─ MicroXRCEAgent (UDP 8888) ◀────────┘
                                  └──────────── 双方经交换机同网段 10.41.10.0/24 ────┘
```

**PX4 端要做的 5 件事：**

| # | 任务 | 类型 |
|---|------|------|
| 1 | 新增 uORB 消息定义 `AirshipBladderPressure.msg` | 复制粘贴（§2） |
| 2 | uXRCE-DDS 话题映射登记 | yaml 加 2 行（§3） |
| 3 | 重新编译固件 | 现有编译流程（§4） |
| 4 | 配置并启动 uxrce_dds_client | 参数/启动脚本（§5） |
| 5 | 控制模块订阅消费代码 | 提供完整骨架，按需集成（§6） |

## 2. 任务 1：新增 uORB 消息定义

将以下内容**一字不改**保存为 `PX4-Autopilot/msg/AirshipBladderPressure.msg`：

```
# 灵云01号 气囊压差同步消息 (树莓派 LoRa 采集 -> uXRCE-DDS -> PX4 飞控)
# 树莓派侧: bladder_bridge_node 发布到 /fmu/in/airship_bladder_pressure
# PX4 侧:   本文件复制到 PX4-Autopilot/msg/ 并在 uxrce_dds_client/dds_topics.yaml
#           的 subscriptions 段登记后, 控制模块以 uORB 话题 airship_bladder_pressure 订阅
#
# 槽位顺序固定为 [左副囊, 左主囊, 右主囊, 右副囊], 对应 LoRa node_id [6,13,14,15], 不可重排
# 压差为相对大气压的有符号值 (Pa), 0 Pa = 与大气压持平; 负值 = 低于大气压

uint64 timestamp			# [us] 树莓派系统时钟; uXRCE-DDS client timesync 自动换算为 PX4 时钟
uint64 timestamp_sample		# [us] LoRa 本轮采样时刻(树莓派时钟), 用于新鲜度判断

# ---- 槽位常量(数组下标) ----
uint8 BLADDER_LEFT_AUX = 0		# 左副囊 (LoRa node_id=6)
uint8 BLADDER_LEFT_MAIN = 1		# 左主囊 (LoRa node_id=13)
uint8 BLADDER_RIGHT_MAIN = 2		# 右主囊 (LoRa node_id=14)
uint8 BLADDER_RIGHT_AUX = 3		# 右副囊 (LoRa node_id=15)

# ---- 4 路压差 [Pa] (相对大气压, 有符号; bridge 从未收到有效数据时为 NaN) ----
float32[4] pressure_delta_pa

# ---- 4 路节点自带温度 [degC] (无效为 NaN) ----
float32[4] temperature_c

# ---- 槽位状态标志 ----
# valid: 1=本轮真实测量(LoRa 本轮 press_valid=1 且非沿用轮)
uint8[4] valid
# stale: 1=该槽位为沿用历史值(LoRa 离线去抖/读取失败/节点缺失), 数值非本轮实测
uint8[4] stale
```

**约束：**
- 字段名、类型、顺序、默认值**任何一个字节都不能改**——DDS 序列化按消息字段完全一致对通，改动任一处则树莓派发来的数据全部丢弃且无报错。
- 文件名必须是 `AirshipBladderPressure.msg`（CamelCase，与生成的话题名 `airship_bladder_pressure` 对应）。
- 无需修改 `msg/CMakeLists.txt`（PX4 构建系统自动扫描 msg/ 目录）。

## 3. 任务 2：uXRCE-DDS 话题映射登记

编辑 `PX4-Autopilot/src/modules/uxrce_dds_client/dds_topics.yaml`，
在 **`subscriptions:`** 列表（这是"ROS2→飞控"方向的条目）末尾追加：

```yaml
  - topic: /fmu/in/airship_bladder_pressure
    type: px4_msgs::msg::AirshipBladderPressure
```

**版本警告（重要）：**
- v1.17 的映射文件就是 `src/modules/uxrce_dds_client/dds_topics.yaml`，格式为 `publications:` / `subscriptions:` / `subscriptions_multi:` 三个列表，**没有 `dir:` 字段**（方向由条目在哪个列表决定）。
- PX4 main 分支/v1.18+ 文档所写 `msg/metadata/Uxrce-dds.yaml`（带 `dir:` 字段）**不适用于 v1.17**，网上教程大多指新路径，别被误导。
- 加在 `subscriptions:`（不是 `publications:`——那是飞控→ROS2 方向）。

登记后 PX4 构建系统（generate_dds_topics.py）自动生成：
- 头文件 `uORB/topics/airship_bladder_pressure.h`
- C 结构体 `airship_bladder_pressure_s`
- client 内部 `uORB::Publication<airship_bladder_pressure_s>`——收到 ROS2 消息即转发到 uORB 话题

## 5. 任务 4：配置并启动 uxrce_dds_client

### 5.1 方式 A（推荐）：SD 卡 extras.txt

在飞控 SD 卡创建/追加 `etc/extras.txt`：

```
uxrce_dds_client start -t udp -p 8888 -h 10.41.10.100
```

### 5.2 方式 B：QGC 参数（等效）

| 参数 | 值 | 说明 |
|------|-----|------|
| UXRCE_DDS_CFG | 2 (Ethernet) | 走以太网口 |
| UXRCE_DDS_PRT | 8888 | Agent 端口 |
| UXRCE_DDS_AG_IP | 170461796 | Agent IP 的 int32 形式（=10.41.10.100；换算: 10*2^24+41*2^16+10*2^8+100） |
| **UXRCE_DDS_DOM_ID** | **5** | **必须设！与树莓派 ROS_DOMAIN_ID=5 一致** |
| UXRCE_DDS_SYNCT | 1 (默认) | 时间同步，保持默认 |

设完参数需重启飞控生效。

### 5.3 关键陷阱（排查前必读）

1. **UXRCE_DDS_DOM_ID 默认 0，不改必然不通！**
   DDS domain 是由 PX4 client 请求、在树莓派 Agent 侧创建的。树莓派节点全部跑 domain 5，client 不设 DOM_ID=5 则数据落在 domain 0，**双方互相看不见，且 Agent 日志看起来一切正常**——这是本链路最大的隐性坑。
2. **以太网口若被 TELEM MAVLink 配置占用，需先释放**（net.cfg/TELEM 配置检查）。
3. 时钟同步无需干预：client 内置 XRCE PING/PONG timesync（UXRCE_DDS_SYNCT 默认开），自动把树莓派 timestamp 换算为 PX4 时钟。

### 5.4 启动验证

飞控 nsh（调试串口）或 QGC MAVLink Console：

```
uxrce_dds_client status
# 预期: running / agent 已连接 (10.41.10.100:8888)
```

树莓派侧同步可见连接日志（树莓派上执行，供联调时核对）：
```
journalctl -u airship-xrce-agent -f
# 预期出现: create_participant / session established (client_key) / create_topic ... rt/fmu/in/airship_bladder_pressure
```

## 6. 任务 5：控制模块消费代码

### 6.1 消息语义契约（必读）

| valid | stale | pressure_delta_pa 含义 | 消费建议 |
|-------|-------|------------------------|----------|
| 1 | 0 | 本轮真实测量（≤2s 新鲜） | 正常使用 |
| 0 | 1 | 沿用最近一次有效值（**非本轮实测**，可能已过期数秒） | 谨慎/降级使用，叠加时间超时 |
| 0 | 0 | `NaN`，该槽位自系统启动以来从未有效 | 不可用 |

**三条铁律：**
1. 消息**始终以 0.5Hz 发布**——即使传感器全断链，也只是内容变为沿用值/NaN，消息流不会停。**禁止用"消息是否到达"判断数据新鲜**。
2. 必须检查 `valid[i]==1 && stale[i]==0` 才可作为本轮实测使用。
3. 必须叠加时间超时 failsafe。LoRa 采集周期 2s + 离线去抖（连续 3 轮失败才判离线）+ 串口重连 → **最坏 ~10s 无真实更新但消息仍在发**。建议：某槽位 >10s 无 valid=1 → 停用该囊相关控制逻辑；>15s → 整体进入安全态。用 `timestamp_sample`（树莓派采样时刻）与 PX4 本地时刻差做超时判断。

NaN 检查：`std::isnan(msg.pressure_delta_pa[i])` 为真表示该槽从未有效。

### 6.2 订阅代码骨架（可直接集成进现有模块）

头文件/成员声明：

```cpp
#include <uORB/Subscription.hpp>
#include <uORB/topics/airship_bladder_pressure.h>

// 类成员:
uORB::Subscription _bladder_sub{ORB_ID(airship_bladder_pressure)};
hrt_abstime _bladder_last_fresh{0};   // 最近一次全槽有效的 timestamp_sample (us)
```

主循环 Run() 内：

```cpp
airship_bladder_pressure_s bd{};
if (_bladder_sub.updated() && _bladder_sub.copy(&bd)) {
  // 槽位常量可直接用消息生成值: bd.BLADDER_LEFT_AUX / BLADDER_LEFT_MAIN / ...
  for (unsigned i = 0; i < 4; ++i) {
    if (bd.valid[i] == 1 && bd.stale[i] == 0 && !std::isnan(bd.pressure_delta_pa[i])) {
      const float dp_pa = bd.pressure_delta_pa[i];   // 本轮实测, 可用
      // ... 各囊控制逻辑 (i=0 左副囊, 1 左主囊, 2 右主囊, 3 右副囊)
    } else if (bd.stale[i] == 1) {
      // 沿用值: 可读 bd.pressure_delta_pa[i] 但非本轮实测, 按降级策略处理
    } else {
      // NaN: 该槽从未有效
    }
  }
  if (bd.valid[0] && bd.valid[1] && bd.valid[2] && bd.valid[3] &&
      !bd.stale[0] && !bd.stale[1] && !bd.stale[2] && !bd.stale[3]) {
    _bladder_last_fresh = bd.timestamp_sample;      // 全槽新鲜才刷新计时
  }
}

// 时间超时 failsafe (0.5Hz 低频链路的兜底):
if (_bladder_last_fresh != 0 &&
    hrt_elapsed_time(&_bladder_last_fresh) > 10_s) {
  // >10s 无全槽新鲜数据: 停用气囊压差相关控制
}
if (_bladder_last_fresh != 0 &&
    hrt_elapsed_time(&_bladder_last_fresh) > 15_s) {
  // >15s: 进入安全态 (按你们的 failsafe 策略)
}
```

注意：
- `timestamp` 字段已被 uXRCE-DDS client 换算为 PX4 时钟基准，可直接用 `hrt_elapsed_time(&bd.timestamp)`；`timestamp_sample` 是树莓派采样时钟（client 同样会做 timesync 偏移换算，误差受 RTT 抖动影响，建议超时阈值留 2s 余量）。
- 若你们已有独立的气囊控制模块，只需把上面的订阅+语义判断嵌入其 Run() 循环；若是新模块，参考 PX4 源码 `src/modules/flight_mode_manager` 的模块骨架（Task/ModuleBase 结构）。

## 7. 端到端验收标准

逐条通过即对接完成：

| # | 验证点 | 命令（飞控 nsh/QGC Console） | 预期 |
|---|--------|------------------------------|------|
| 1 | client 连接 | `uxrce_dds_client status` | running，agent 10.41.10.100:8888 |
| 2 | uORB 数据流 | `listener airship_bladder_pressure 5` | 每 ~2s 一条，共 5 条 |
| 3 | 槽位数据正确性 | 同上，对照树莓派侧 | 树莓派执行 `ros2 topic echo /fmu/in/airship_bladder_pressure`（需 `unset RMW_IMPLEMENTATION CYCLONEDDS_URI; export ROS_DOMAIN_ID=5`），4 槽压差值一致 |
| 4 | 负值传递 | 同上 | 台架传感器未装舱时可能出现 -30~-60 Pa 量级负值（传感器零漂/气流），**负值是正常的**（相对大气压有符号） |
| 5 | 语义标志 | 同上 | 传感器正常时 valid=[1,1,1,1], stale=[0,0,0,0] |
| 6 | 断链 failsafe | 拔掉树莓派侧 LoRa 串口或停 sensor | 消息仍 0.5Hz 到达，但 stale 逐渐变 1；>10s 后你的控制逻辑应触发停用 |
| 7 | 频率确认 | `uorb top` | airship_bladder_pressure ~0.5Hz |

## 8. 故障排查表

| 症状 | 原因 | 处置 |
|------|------|------|
| `listener airship_bladder_pressure` 无输出，`uxrce_dds_client status` 显示已连 | UXRCE_DDS_DOM_ID 未设 5 | 设 5 并重启（§5.3 第 1 条） |
| client 连不上 agent | 飞控→树莓派 UDP 8888 不通 / IP 配错 | ping 10.41.10.100；核对 AG_IP int32 换算 |
| dds_topics.yaml 改了但没生效 | v1.17 文件路径错（改成了 Uxrce-dds.yaml）或没重编固件 | 用 §3 的正确路径；重新编译 |
| msg 字段对不上（数据全 0/丢弃） | msg 文件被改动过任何字节 | 与 §2 逐字节 diff |
| 树莓派侧看不到话题（调试时） | 交互 shell 默认 CycloneDDS 与生产 Fast DDS 不同族 | `unset RMW_IMPLEMENTATION CYCLONEDDS_URI` 后再 echo |
| 重启飞控后链路断 | extras.txt 未生效或参数方式未重启 | 优先用方式 A；QGC 参数必须重启 |
