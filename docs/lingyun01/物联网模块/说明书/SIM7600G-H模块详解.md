# SIM7600G-H 4G 模块详解

> 适用硬件：微雪4G拓展板 + SIMCOM SIM7600G-H-M2 模块（树莓派5）
> 本文面向想深入了解该模块的设计、功能与用法的读者，从硬件到软件层层拆解。

## 一、模块概述

SIM7600G-H 是 **SIMCom（芯讯通）** 推出的一款 **LTE Cat 4 全网通无线通信模组**，集成：

- 2G/3G/4G 蜂窝通信
- GNSS 卫星定位（GPS/北斗/GLONASS/Galileo/QZSS）
- 内置 TCP/IP 协议栈
- UART / USB / GPIO 等多种接口

**一句话定位**：它是一个"能打电话、能发短信、能联网、能定位"的**独立通信核心**。你只需要通过串口/USB 发 AT 指令，它就能帮你完成所有蜂窝网络通信。

### 3.2 两种工作形态

1. **AT 指令模式**：通过 UART 串口发 AT 指令，模块独立完成联网/收发。适合**单片机、无操作系统**的设备。
2. **系统网卡模式**：通过 USB（qmi_wwan/RNDIS）让操作系统把模块识别为**网卡**，走系统网络栈。适合 Linux/Windows（本项目即此形态）。

## 四、什么是 AT 指令？

### 4.1 AT 指令的本质

**AT 指令（Attention Command）是一套"人类/主控 ↔ 通信模块"之间的文本命令协议。** 它是通信模块行业的事实标准，由 Hayes 于 1981 年提出（所以也叫"Hayes 指令集"）。

- 每条指令以 **`AT` 开头**，以回车结尾。
- 模块收到后执行，并返回结果，如 `OK` / `ERROR` / `+CSQ: 20,99`。
- 早期用于 Modem，现广泛用于手机基带、4G/5G 模块、WiFi/BT 模块。

### 4.2 基本格式

```
AT<命令>           ← 主控发给模块
<结果>             ← 模块返回，通常以 OK/ERROR 结尾
```

示例：
```
AT                  → OK                        （握手测试）
AT+CSQ              → +CSQ: 20,99              （查询信号）
AT+CPIN?            → +CPIN: READY              （查询SIM状态）
AT+CGDCONT=1,"IP","CMNET"  → OK                （设置APN）
```

### 4.3 三类 AT 命令

| 类型 | 写法 | 说明 |
|---|---|---|
| 测试型 | `AT+CMD=?` | 查询命令支持的参数范围 |
| 查询型 | `AT+CMD?` | 查询当前参数值 |
| 设置型 | `AT+CMD=<参数>` | 设置参数并执行 |

### 4.4 重要概念：URC（主动上报）

模块**不请自来**推送的消息叫 **URC（Unsolicited Result Code）**。例如收到短信、来电、网络断开时，模块会主动向串口推送：

```
+CMTI: "SM",1          ← 有新短信
+CIEV: 5,1             ← 网络事件
```

**理解 URC 很重要**：主控程序要**随时监听串口**，不能只在发指令后读取，否则会漏掉模块主动推送的消息。

## 五、AT 指令 与 透传 的关系（常见误区）

你问"AT 指令是透传吗"——**不是，两者是两种不同的工作模式**。

| | AT 指令模式 | 透传模式 |
|---|---|---|
| 数据流 | 指令和响应混杂在串口 | 纯数据，透明转发 |
| 适合 | 控制、配置、查询 | 持续大数据收发 |
| 例子 | `AT+CIPSTART` 建连 | `AT+CIPMODE=1` 后直接传业务数据 |

**关系**：先用 AT 指令**配置和建立连接**，然后**切换进透传模式**持续传数据，最后切回 AT 模式做控制。二者互补，不冲突。

### 5.1 官方 TCP/IP 标准流程（SIM7600 新协议栈）

SIM7600 系列用的是 **`NETOPEN`/`CIPOPEN`** 这套（非老式 `CIPSTART`）：

```at
AT+CGDCONT=1,"IP","CMNET"                    # 设置 APN（GPRS 卡需开通联网功能）
AT+CSQ                                        # 检查信号（第一个值越大越强，最大31）
AT+CREG?                                      # 检查注册（第二参数为1=注册成功）
AT+CIPMODE=1                                  # 开启 TCP/IP 透传模式
AT+CSOCKSETPN=1                               # 选择 TCP/IP 应用模式
AT+NETOPEN                                    # 打开网络（返回 OK 即网络已开）
AT+CIPOPEN=0,"TCP","服务器IP",端口            # 建立 TCP 连接
# 成功进入透传，串口发什么发到对端，对端发来的从串口出
+++                                           # 延迟发送，退出透传
AT+CIPCLOSE=0                                 # 关闭 TCP 连接
AT+NETCLOSE                                   # 关闭网络
```

### 5.2 非透传模式示例（按长度发送，适合程序控制）

```at
AT+CIPMODE=0                                 # 关闭透传（普通模式）
AT+NETOPEN                                   # 打开网络
AT+CIPOPEN=0,"TCP","服务器IP",端口           # 建连
AT+CIPSEND=0,<长度>                           # 发送指定长度数据
> <这里输入数据>                              # 出现 > 后发送
AT+CIPCLOSE=0                                # 关闭
```

> 注意：SIM7600 也兼容部分老式 `AT+CIPSTART` 用法，但官方推荐使用 `NETOPEN`/`CIPOPEN` 体系。发送 AT 时务必在串口工具中勾选"加回车换行"。

### 5.3 4G 透传的应用场景（什么情况下该用透传）

**透传的本质特征**：把串口数据**原样**转成网络数据，中间**不做任何协议转换**。模块内置 TCP/IP 栈，你的串口发什么就原样发给对端，对端发来的也原样从串口出——你不需要关心 IP 协议细节，只当它是一条"会联网的虚拟串口线"。

这一特性决定了透传的**主要应用场景**：

| 场景 | 说明 | 典型例子 |
|---|---|---|
| **无 OS 的 MCU/单片机设备上网**（最核心） | 单片机没有 Linux、跑不了 TCP/IP，透传让它们**不写任何网络代码就能联网** | STM32/51 采集器、电表、水表、PLC 数据远程回传 |
| **传统串口设备的远程化改造** | 原本只有本地串口的设备，通过透传变成**网络可达**，异地可访问 | 远程串口服务器、现场仪表远程监控、老设备（RS232/RS485）联网 |
| **串口透传组网 / 虚拟串口** | 两端都是 4G 透传模块，借助打洞/组网工具把两端串口"接"成一根虚拟线 | 异地设备远程调试、工业上下位机跨地域直连 |
| **简单原始数据上行** | 只需要"把一串数据发上去"、不在乎格式时 | 温湿度/GPS/液位等周期性上报 |

**一句话**：4G 透传 = "没有操作系统的串口设备要联网/远程访问"的捷径。

### 5.4 透传 vs 系统网络栈（本项目为什么不透传）

透传虽方便，但有明显**局限**，本项目的机载 ROS2 场景恰好踩中：

| 对比项 | 4G 透传（AT 模式） | 系统网络栈（网卡模式，本项目） |
|---|---|---|
| 运行平台 | 裸机/单片机 | 有 OS 的设备（树莓派 Linux） |
| 数据流 | 串口 ↔ 模块 ↔ 网络 | 系统协议栈（socket/MQTT/TCP） |
| 可靠性 | 仅"转发"，无确认/重传/缓存 | 完整的 TCP 可靠传输、应用层协议 |
| 多路并发 | 以单连接为主，难做多路管理 | 可同时跑多进程/多 topic |
| 对端确定 | 需写死固定公网 IP | 可用 MQTT 主题寻址，绕开 NAT |
| 数据量瓶颈 | 受串口速率限制 | 受 4G 带宽限制，通常更高 |
| 扩展性 | 弱，协议耦合在串口 | 强，可接任意应用 |

**结论**：本项目的场景是"机载 ROS2 + 多设备状态 + 飞控遥测 + 可能的视频"，需要**可靠的系统级网络（TCP/MQTT、多路复用、可靠传输）**，而不是"裸转发"。所以架构走 **wwan0 系统网卡 + MQTT/TCP**，**不使用透传**。透传是给裸机设备的一条捷径，而树莓派不需要走捷径。

## 六、如何接入模块（用法）

### 方式 A：UART 直连（适合单片机/MCU）

- 模块 UART：TX/RX（注意与主控交叉连接：模块TX→主控RX）。
- 接线端子供电 5-12V。
- 波特率默认 115200（可 `AT+IPREX` 修改）。
- 用串口终端发 AT 指令，或写 MCU 程序驱动。

### 方式 B：USB 接入系统（本项目，树莓派）

- USB 连树莓派，驱动 `option`+`qmi_wwan` 自动加载。
- 出现 `ttyUSB0-4`（AT口/GPIO/GPS/AT/audio）和 `wwan0`（网卡）。
- 用 ModemManager 拨号，`wwan0` 变成系统网卡。

本项目已用方式 B 打通联网，详见 [4G模块调试指南.md](./4G模块调试指南.md)。

### 方式 C：RNDIS 拨号（官方推荐的树莓派方式）

微雪官方在树莓派上常用 RNDIS（USB 虚拟网卡）方式，先切换 PID 再 `dhclient`：

```bash
sudo apt-get install minicom
sudo minicom -D /dev/ttyUSB2       # 打开 AT 口
# 在 minicom 内发送：
#   AT+CUSBPIDSWITCH=9011,1,1     # 切换到 RNDIS 模式
sudo dhclient -v usb0              # 用 dhclient 获取 usb0 网卡 IP
```

> 本项目用的是 ModemManager/QMI 方式（更现代、可配置开机自动联网），RNDIS 是另一条可选路径，二者选一即可。

## 七·补、GNSS 定位调试

GPS/北斗为模块一大特色，调试要点：

```at
AT+CGPS=1        # 打开 GPS
AT+CGPSINFO      # 将定位信息打印到串口
AT+CGPS=0        # 关闭 GPS
```

**关键注意事项**：
- **必须接 GPS 天线**（GNSS 座），并将接收器置于**空旷室外**（阴雨天测不了）。
- 上电后需等待**约 1 分钟**才能搜到定位信号，属正常现象。
- M.2 模组一般用**无源 GPS 天线**；若没有，也可用 4G/5G 天线临时替代测试。
- `AT+CGPSINFO` 返回的是一串逗号分隔的经纬度/时间等字段，需按手册解析。
- 也支持 **LBS 基站定位**（无卫星时可作辅助）。

## 八、点对点通讯（结合你的需求）

模块支持通过互联网与另一设备点对点通讯，两种路径：

### 路径 1：AT 指令 + 模块内置 TCP/UDP（UART 场景）
见上文 5.1/5.2，直接 `AT+CIPSTART` 连对端。

### 路径 2：系统网卡 + socket/MQTT（本项目 Linux 场景）
把 `wwan0` 当普通网卡，用任意 TCP/UDP 应用通讯。

**⚠️ 关键限制**：4G 卡拿到的是运营商**私网 IP**（本项目 `10.181.40.79`），对端**无法主动连进来**（NAT）。解决：

1. 一端用**有公网 IP 的服务器**，树莓派主动连它；
2. 两端连同一个 **MQTT broker**（云上），通过主题收发；
3. 用 **frp/WireGuard 内网穿透**。

对机载遥测回传，推荐"树莓派主动连云端 MQTT/TCP 服务器"。

## 九、本项目中的角色与下一步

- 当前：模块已作为树莓派的 4G 网卡联网成功（wwan0，IP `10.181.40.79`）。
- 数据链路设想：BMS/MPPT/DCDC 状态 → CAN → 树莓派 airship_* 节点 → 4G(wwan0) → 云端/服务器。
