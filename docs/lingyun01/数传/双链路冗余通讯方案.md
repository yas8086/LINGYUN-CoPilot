# 双数传链路冗余通讯 技术方案

> **版本**：V1.0
> **状态**：方案设计（待确认硬件前提后实施）
> **关联**：L33（主）、L39（备）双数传链路

---

## 一、方案背景

飞艇机载需要可靠的远距通讯链路。单个数传（L33）存在单点故障风险——无线断链、数传故障都会导致地面失去与机载的联系。本方案通过 **L33 + L39 双数传链路冗余**，保证一条链路故障时另一条仍能工作，提升通讯可靠性。

---

## 二、物理拓扑

```
【机载侧】                                       无线(2对独立)      【地面侧】
飞控 Telem1 ──TTL── L33 UART1 ═════════════════ 地面L33 ──串口── QGC(主)
飞控 Telem2 ──TTL── L39 UART1 ═════════════════ 地面L39 ──串口── QGC(备)

飞控 ──ETH──────────┐
树莓派 ──(多IP)─────┼── 交换机 ── L33网口(192.168.10.254)
树莓派 ─────────────┼── 交换机 ── L39网口(192.168.20.254)
摄像头×N ──ETH──────┘
```

**双链路构成**：
1. **串口链路**：L33 UART1↔飞控Telem1（主遥测）、L39 UART1↔飞控Telem2（备遥测）
2. **网络链路**：L33网口→网段A（192.168.10.x）、L39网口→网段B（192.168.20.x）

---

## 三、核心设计

### 3.1 冗余策略：双发并发，丢一路没事

- 树莓派**同时**向 L33、L39 两个数传转发需上报的数据（飞控遥测、BMS/4G等汇聚数据）
- 两路无线链路**互相独立**，一路故障不阻塞另一路
- 地面端任一路收到即可，天然冗余，无需复杂切换

### 3.2 分网段隔离（防广播冲突）

| 数传 | 机载网口IP | 无线网段 | 地面网段 |
|---|---|---|---|
| **L33**（主） | 192.168.10.254 | 网段A | 192.168.10.x |
| **L39**（备） | 192.168.20.254 | 网段B | 192.168.20.x |

- 两数传**分属不同网段**，各自网桥桥接独立子网
- **避免两个网桥接同一交换机引发的 MAC 漂移 / 广播风暴**
- 无线信道需**错开**，防止两对互相干扰

### 3.3 树莓派多网段接入

eth0 绑定多个静态 IP，同时访问飞控、L33、L39：

```yaml
addresses:
- "10.41.10.100/24"      # 飞控
- "192.168.10.100/24"    # L33 网段A
- "192.168.20.100/24"    # L39 网段B
```

### 3.4 数据上报

- **飞控遥测**：经 L33/L39 串口与网口双路并发上报，地面任意链路可收
- **BMS/4G/机载业务数据**：树莓派汇聚后**同时发往两个数传网口 IP**，双链路冗余上报
- 分网段后，两条 UDP/TCP 路径完全独立

## 五、实施步骤（硬件确认后）

### Step 1：硬件接线
```
飞控Telem1 → L33 UART1          L33网口 → 交换机
飞控Telem2 → L39 UART1          L39网口 → 交换机
树莓派/camera → 交换机
```
- 确认 2 对 L33/L39 配对正确
- 两对无线信道错开

### Step 2：数传 IP 配置
- 确认/修改 L39 网口 IP = 192.168.20.254（与 L33 的 .10 网段分开）
- 用数传专用配置工具设置

### Step 3：树莓派加第三 IP
```bash
sudo nmcli connection modify "netplan-eth0" +ipv4.addresses "192.168.20.100/24"
sudo nmcli connection up "netplan-eth0"
ip -4 addr show eth0   # 确认三个 IP
```

### Step 4：验证双链路
```bash
# L33 链路
ping -c2 192.168.10.254
# L39 链路
ping -c2 192.168.20.254

# 飞控遥测经两路并发
python3 # 分别向两数传网口发 MAVLink，验证都能通
```

### Step 5：数据并发上报
- 树莓派上报逻辑：数据同时发往 192.168.10.254 + 192.168.20.254
- 验证断开一路，另一路继续

## 六、风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 两数传 IP 冲突 | 接了不工作 | L33/L39 分网段(.10/.20) |
| 两对无线同频干扰 | 两路都不稳 | 配置不同信道 |
| 配对错误 | 地面收不到 | 严格按 L33对/L39对 配对 |
| 双网桥广播冲突 | 数据重复 | 分网段隔离 |
| 带宽共享 | 多路拥堵 | 数传只承担轻量通讯，视频走独立图传 |
