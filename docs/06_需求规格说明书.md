## 1. 引言

### 1.1 目的
定义伴飞电脑系统的需求规格，作为开发、测试、验收与交付的统一基准。

### 1.2 范围
系统面向飞艇搭载场景，承担机载设备数据的中继、监控、告警、安全仲裁与上云。当前交付范围为：
- **Phase-1 设备监控**：锂电池 BMS / 光伏 MPPT / DCDC 电源模块 / LoRa 温度压力采集
- **飞控监控**：通过 MAVROS 采集 PX4 飞控状态并做异常检测（监控为主，不下发控制）
- **数据链路**：串口数传下传地面站 + 4G MQTT 上云

**明确不在本期范围**：飞行控制指令下发、路径规划、自主飞行控制。

### 1.3 术语

| safe_to_control | 安全总开关，false 时禁止任何控制指令下发 |
| dcdc_hold | 无 ROS 依赖的 DCDC 硬件保活进程 |
| 数传 | 串口链路下传地面站 |

## 2. 总体描述

### 2.1 产品视角
伴飞电脑作为**机载数据中继节点**，从 CAN 总线（BMS/MPPT/DCDC）、485 串口（LoRa 集中器）、以太网（飞控 MAVLink）采集数据，解析后：
1. 经串口数传下传地面 Qt 上位机；
2. 经 4G + MQTT 上云；
3. 本地做看门狗、告警、安全仲裁。

```
 BMS/MPPT/DCDC ──CAN(250kbps)──► 树莓派5 ──┬─► 串口数传 ──► 地面站
 LoRa集中器   ──RS485(9600)───►           ├─► 4G/MQTT ──► 云
 PX4飞控      ──ETH UDP:14550─► MAVROS    └─► 本地看门狗/告警/安全仲裁
```

### 2.2 运行环境
| 项 | 规格 |
|---|---|
| 硬件 | Raspberry Pi 5（ARM64） |
| OS | Ubuntu 24.04 LTS |
| 中间件 | ROS2 Jazzy |
| CAN | SocketCAN `can0`，250kbps，扩展帧 |
| 飞控接入 | 以太网 eth0 静态 IP `10.41.10.100/24`，MAVLink over UDP `:14550` |

### 2.3 假设与依赖
- A1：USB-CAN 适配器已接入并可识别为 `can0`。
- A2：各设备厂家 CAN/Modbus 协议与 [02_CAN协议汇总](./02_CAN协议汇总.md) 及厂家原文一致。
- A3：数传电台与 4G 模块的 VID/PID 已按 [04_生产部署清单](./04_生产部署清单.md) 配置 udev 固定命名。
- A4：飞控侧已配置静态 IP 与 MAVLink UDP 输出（见 [05_飞控监控与联调](./05_飞控监控与联调.md)）。

### 2.4 约束
- 消息定义必须集中在独立 `airship_msgs` 包，避免循环依赖。
- 核心业务逻辑抽为 ROS 无关纯库，保证可 gtest 测试。
- 依赖结构必须为向下单向 DAG：`airship_msgs → can/utils → 驱动 → monitor/link/safety → bringup`。

## 3. 系统功能需求

### 3.1 BMS 电池监控（FR-BMS）
- FR-BMS-01：解析 102 串三元锂电池总压、总电流、SOC、RealSOC。
- FR-BMS-02：解析各单体电压，并计算最高/最低单体电压与压差。
- FR-BMS-03：解析最高/最低/平均电芯温度与温差、8 点极耳温度。
- FR-BMS-04：解析正负极绝缘电阻与告警级别（0 正常 / 1 故障 / 2 严重）。
- FR-BMS-05：以 `/bms/status`（BmsStatus）发布聚合状态。
- FR-BMS-06：CAN 接口掉线自动重连；短帧（DLC 不足）安全忽略。

### 3.2 MPPT 光伏监控（FR-MPPT）
- FR-MPPT-01：以 1Hz 查询并解析 MPPT 光伏电压、电池电压、充电电流。
- FR-MPPT-02：解析额定参数、充电/故障状态、日/月/总发电量、模块温度、控制模式。
- FR-MPPT-03：以 `/mppt/status`（MpptStatus）发布。
- FR-MPPT-04：回应帧校验源设备地址，防多设备总线串扰。

### 3.3 DCDC 电源监控与控制（FR-DCDC）
- FR-DCDC-01：以 5Hz 持续下发电源控制帧（输出电压设定 48V、限流设定），满足厂商 200ms 周期要求。
- FR-DCDC-02：以 1Hz 查询模拟量（输入/输出电压、电流、温度）。
- FR-DCDC-03：解析电源状态帧故障字与输出使能位。
- FR-DCDC-04：`dcdc_hold` 独立进程以 200ms 周期保活输出，**即使 ROS2 崩溃仍保持 DCDC 不断电**。
- FR-DCDC-05：以 `/dcdc/status`（DcdcStatus）发布。

### 3.4 LoRa 温度/压力采集（FR-LORA）
- FR-LORA-01：经 RS485 以 Modbus RTU 轮询集中器，采集 3 个 LoRa 节点（2 温度 + 1 压力）。
- FR-LORA-02：采集周期 2000ms；温度报警阈值 -10℃ ~ +60℃。
- FR-LORA-03：以 `/lora/samples`、`/lora/summary` 发布；提供 `/lora/query_node`、`/lora/query_summary` 服务。
- FR-LORA-04：串口掉线自动重连；节点寄存器地址越界（uint16 回绕）时跳过并告警。

### 3.5 串口数传链路（FR-LINK）
- FR-LINK-01：订阅 BMS/MPPT/DCDC/LoRa 最新状态并缓存。
- FR-LINK-02：以 5Hz（200ms）聚合打包为单行 JSON（帧头 `0xAA 0x55` + `\n`）经串口下传地面站。
- FR-LINK-03：串口掉线按重连周期自动恢复；写入失败告警。

### 3.6 监控/看门狗（FR-MONITOR）
- FR-MONITOR-01：以 1Hz 看门狗检测各设备在线状态。
- FR-MONITOR-02：设备超时（3s）离线判定并产生告警。
- FR-MONITOR-03：告警去重，避免刷屏。

### 3.7 安全仲裁（FR-SAFETY）
- FR-SAFETY-01：订阅 DCDC 状态，聚合判据并发布 `/safety/status`（SafetyStatus）。
- FR-SAFETY-02：**fail-safe**：启动即 `safe_to_control=false`；DCDC 无数据/超时（3s）或故障时置 `safe_to_control=false`。
- FR-SAFETY-03：以 10Hz 发布安全状态，附原因（reason）。

### 3.8 飞控监控（FR-FC）
- FR-FC-01：经 MAVROS 采集飞控状态（位置、姿态、气压高度、空速、油门、飞行模式、电量等）。
- FR-FC-02：多级异常检测（高度、速度、电池电压/剩余电量、角速度等），连续去抖（N=3）后触发告警，避免毛刺误报。
- FR-FC-03：以 `/fc/status`（FlightStatus）与 `/fc/alert`（FcAlert）发布，以 10Hz 聚合。
- FR-FC-04：未连接或电池未上报时不得触发 EMERGENCY 误报。

### 3.9 4G 上云（FR-CLOUD）
- FR-CLOUD-01：经 MQTT（TLS 8883）以 2Hz 上云发布遥测到 `lingyun01/telemetry`。
- FR-CLOUD-02：MQTT 断线自动重连。
- FR-CLOUD-03：凭据安全：密码经环境变量 `MQTT_PASSWORD` 注入，不得出现在进程命令行。

### 3.10 启动编排（FR-BRINGUP）
- FR-BRINGUP-01：一键启动全部监控节点（BMS/MPPT/DCDC/LoRa/Monitor/Link/Safety/FC/Cloud/MAVROS）。
- FR-BRINGUP-02：每个节点 `respawn=True`，崩溃自动重启。

### 3.11 工程化（FR-ENG）
- FR-ENG-01：systemd 开机自启与崩溃自愈（`Restart=always`）。
- FR-ENG-02：udev 固定设备命名（`/dev/airship_485`、`/dev/airship_link`、`/dev/airship_4g_at*`）。
- FR-ENG-03：日志上限（journald 50MB、ROS logrotate）防 TF 卡撑爆。
- FR-ENG-04：NTP 时间同步。
- FR-ENG-05：CI 双架构（x86_64/arm64）编译 + lint + 测试。

## 4. 外部接口需求（IF）

| 编号 | 接口 | 说明 |
|---|---|---|
| IF-CAN | SocketCAN `can0` 250kbps 扩展帧 | BMS/MPPT/DCDC 数据接入 |
| IF-485 | RS485 9600，Modbus RTU | LoRa 集中器采集 |
| IF-ETH | eth0 静态 IP，MAVLink UDP 14550 | 飞控接入 |
| IF-LINK | 串口 115200，`0xAA 0x55 [JSON]\n` | 地面站数传（见地面站对接协议） |
| IF-MQTT | TLS 8883，topic `lingyun01/telemetry` | 4G 上云 |
| IF-ROS | 话题/服务见各消息定义（airship_msgs） | 内部节点通信 |

**消息/服务清单**：`BmsStatus`、`MpptStatus`、`DcdcStatus`、`FlightStatus`、`FcAlert`、`SafetyStatus`、`DeviceAlert`、`LoRaSample(s)`、`LoRaSummary`、`QueryNode.srv`、`QuerySummary.srv`。

## 5. 非功能需求

### 5.1 性能（PR）
| 编号 | 指标 | 要求 |
|---|---|---|
| PR-01 | MPPT 查询频率 | ≥ 1Hz |
| PR-02 | DCDC 控制帧频率 | 5Hz（厂商 200ms 要求） |
| PR-03 | LoRa 采集周期 | 2000ms |
| PR-04 | 数传下传频率 | 5Hz（200ms） |
| PR-05 | 上云发布频率 | 2Hz |
| PR-06 | 看门狗检测频率 | 1Hz，离线判定 ≤ 3s |
| PR-07 | 安全状态发布 | 10Hz，DCDC 判据超时 ≤ 3s |
| PR-08 | 飞控状态发布 | 10Hz，掉线判定 ≤ 2s |
| PR-09 | 串口数传单帧 | 可变长电芯数据（≤ ~400B BMS），避免固定 2KB 浪费 |
| PR-10 | 崩溃恢复 | 节点 respawn ≤ 2s；服务 RestartSec=3s |

### 5.2 可靠性（RR）
- RR-01：CAN 接口掉线自动重连。
- RR-02：串口（数传/LoRa）掉线自动重连。
- RR-03：MQTT 断线自动重连。
- RR-04：任一端点崩溃由 respawn/systemd 自愈。
- RR-05：`dcdc_hold` 独立进程，ROS2 全崩仍保持 DCDC 输出。

### 5.3 安全（SR）
- SR-01：未满足安全判据时 `safe_to_control` 必须为 `false`（fail-safe 默认关闭）。
- SR-02：MQTT 密码不得明文出现在进程命令行。
- SR-03：飞控接入为监控模式，**不主动下发控制指令**。

### 5.4 可维护性 / 可测试性（MR）
- MR-01：核心逻辑为 ROS 无关纯库，可用 gtest 单测。
- MR-02：依赖为单向 DAG，无循环依赖。
- MR-03：部署可重复执行（`install_production.sh`）。

## 8. 验收标准（Acceptance Criteria）

### 8.1 验收流程
1. 部署环境按 [04_生产部署清单](./04_生产部署清单.md) 执行并跑通第 7 节验证清单。
2. 逐条对照第 3~5 节需求项，在验收记录中打勾/注明。
3. 通过下述验收用例（ATC）方判定通过。

### 8.2 功能验收用例（ATC-F）
| 编号 | 用例 | 通过标准 |
|---|---|---|
| ATC-F-01 | 上电启动 | `systemctl status airship-device-monitor` 为 active，`ros2 node list` 含 9+ 节点 |
| ATC-F-02 | BMS 数据 | `ros2 topic echo /bms/status` 总压/SOC/单体电压合理且随设备变化 |
| ATC-F-03 | MPPT 数据 | `/mppt/status` 各字段与设备一致 |
| ATC-F-04 | DCDC 输出 | DCDC 保持输出，`/dcdc/status` 输出使能为真 |
| ATC-F-05 | dcdc_hold 保活 | 停止 ROS2 系统后 DCDC 仍保持输出 |
| ATC-F-06 | LoRa 采集 | `/lora/summary` 显示 3 节点在线且温度/压力合理 |
| ATC-F-07 | 数传下传 | 地面站按 `0xAA 0x55 [JSON]\n` 收到 5Hz 遥测 |
| ATC-F-08 | 上云 | 云端收到 `lingyun01/telemetry` 2Hz 遥测 |
| ATC-F-09 | 安全仲裁 | DCDC 异常时 `/safety/status` 的 `safe_to_control=false` 且含 reason |
| ATC-F-10 | 飞控监控 | 飞控接入后 `/fc/status` 10Hz 更新；拔线 2s 内判离线 |
| ATC-F-11 | 看门狗 | 拔掉某设备 3s 内产生对应告警 |

### 8.3 可靠性验收用例（ATC-R）
| 编号 | 用例 | 通过标准 |
|---|---|---|
| ATC-R-01 | CAN 拔插恢复 | 重新插回 USB-CAN 后自动重连，数据恢复 |
| ATC-R-02 | 串口拔插恢复 | 数传/LoRa 串口重插后自动重连 |
| ATC-R-03 | 节点崩溃自愈 | kill 任一节点，≤2s 自动重启恢复 |
| ATC-R-04 | 服务崩溃自愈 | kill 主服务，RestartSec=3 后自动拉起 |
| ATC-R-05 | MQTT 断线恢复 | 断网后恢复自动重连上云 |

### 8.4 性能验收用例（ATC-P）
| 编号 | 用例 | 通过标准 |
|---|---|---|
| ATC-P-01 | 采样频率 | MPPT 1Hz / LoRa 2Hz / 数传 5Hz / 上云 2Hz / 飞控 10Hz，均达标 |
| ATC-P-02 | 离线判定 | 设备 3s、飞控 2s 内判离线 |
| ATC-P-03 | 恢复时间 | 节点 respawn ≤ 2s，服务重启 ≤ 3s + 启动时间 |
| ATC-P-04 | 带宽 | BMS 单帧 ≤ ~400B（可变长电芯） |

### 8.5 安全验收用例（ATC-S）
| 编号 | 用例 | 通过标准 |
|---|---|---|
| ATC-S-01 | fail-safe | 启动初期 `safe_to_control=false`；判据异常即关断 |
| ATC-S-02 | 凭据 | `ps`/`/proc/<pid>/cmdline` 不含 MQTT 明文密码 |
| ATC-S-03 | 飞控只读 | 监控期间飞控无收到本系统控制指令 |

### 8.6 回归与质量门槛
| 编号 | 项 | 门槛 |
|---|---|---|
| ATC-Q-01 | 单元测试 | `colcon test` 全部通过，0 失败 |
| ATC-Q-02 | 集成测试 | 模拟脚本（sim_bms/sim_px4/sim_mqtt_verify 等）通过 |
