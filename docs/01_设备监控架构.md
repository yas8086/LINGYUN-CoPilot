# 灵云01号 设备监控架构

## 1. 系统概述

树莓派5 作为**机载数据中继节点**,通过 CAN 总线接收各电源设备数据,解析后统一经串口数传下传给地面 Qt 上位机。

```
┌──────────────────────────── 树莓派5 (伴飞电脑) ────────────────────────────┐
│                                                                            │
│  MPPT ──┐                                                                 │
│  BMS  ──┼── CAN (SocketCAN can0, 250kbps) ──► airship_* 节点 ──► link_node│
│  DCDC ──┘                                                                  │
│  备用电源BMS ── 串口(北辰协议 9600 8N1) ──► backup_bms_node ─► /backup_bms/status
│  飞控  ── 网口 ETH(UDP 14550) ──► MAVROS(PX4) ──► fc_monitor ──► /fc/status│
│  4G   ──► cloud_node(MQTT) ──► 公有云(地址待定)                              │
│  LoRa ──► 485(Modbus RTU) ──► lora_node ──► /lora/samples /lora/summary     │
│                                                                              │
│  设备驱动:  bms_node / backup_bms_node / mppt_node / dcdc_node              │
│  LoRa采集:  lora_node (485 Modbus RTU 轮询集中器)                            │
│  飞控监控:  fc_monitor_node (MAVROS 聚合)                                    │
│  状态聚合:  monitor_node (告警/日志/看门狗)                                  │
│  安全仲裁:  safety_node (safe_to_control, 聚合 DCDC/BMS/备用电源)            │
│  数传链路:  link_node (JSON打包, 串口下传)                                   │
│  4G 上云:   cloud_node (MQTT 汇总上报)                                       │
└──────────────────────────────────────────────────────────────────────────┘
                                                                              │
                                                             串口 (Linux 串口)
                                                                              ▼
                                                        地面 Qt 上位机 (解析显示)
```

## 2. 硬件与接口

| 项目 | 参数 |
|------|------|
| 主控 | Raspberry Pi 5 (8GB) |
| 系统 | Ubuntu 24.04 LTS + ROS2 Jazzy |
| CAN 接入 | USB-CAN 适配器 → SocketCAN `can0` |
| CAN 波特率 | 250 kbps (各设备一致) |
| CAN 帧类型 | 扩展帧 (29位 ID) |
| 备用电源 BMS | 12S 备用锂电池 BMS, 串口(北辰协议 V1.4, 9600 8N1, 默认 /dev/airship_backup_bms) |
| 数传 | 串口模块 (默认 /dev/ttyUSB0, 115200 baud) |
| 飞控 | 雷迅 X25 EVO, 二次开发 PX4, 网口 ETH (飞控 IP 10.41.10.2:14550, 树莓派 eth0 10.41.10.100/24) |
| LoRa 采集 | LoRa 温度/压力集中器, USB-RS485 → Modbus RTU (默认 /dev/ttyUSB0, 9600 baud) |
| 4G 上云 | SIM7600G-H4G + MQTT(libmosquitto), Broker 地址待定 |

## 3. 软件包结构

```
src/
├── airship_msgs/        # 设备监控消息定义 (BmsStatus/MpptStatus/DcdcStatus/DeviceAlert/FlightStatus/LoRaSample/LoRaSamples/LoRaSummary)
├── airship_can/         # SocketCAN 抽象层 (收发帧)
├── airship_utils/       # 可测工具库 (CAN解析/单位换算/限幅/四元数转欧拉角)
├── airship_bms/         # 主 BMS 驱动节点
├── airship_backup_bms/  # 12S 备用电源 BMS 驱动节点 (串口, 北辰协议 V1.4)
├── airship_mppt/        # MPPT 驱动节点
├── airship_dcdc/        # DCDC 驱动节点
├── airship_fc/          # 飞控数据监控节点 (MAVROS 聚合 -> /fc/status)
├── airship_lora/        # LoRa 温度/压力采集节点 (485 Modbus RTU 轮询集中器)
├── airship_cloud/       # 4G 上云节点 (MQTT 汇总上报)
├── airship_safety/      # 安全仲裁节点 (safe_to_control)
├── airship_monitor/     # 设备监控聚合节点 (告警/看门狗)
├── airship_link/        # 串口数传链路节点 (JSON 下传)
└── airship_bringup/     # launch + 参数配置
```

## 4. 节点拓扑与话题

```
[ bms_node ]  ---> /bms/status    (BmsStatus)
[ backup_bms_node ] ---> /backup_bms/status (BackupBmsStatus)   <- 串口(北辰协议)
[ mppt_node ] ---> /mppt/status   (MpptStatus)
[ dcdc_node ] ---> /dcdc/status   (DcdcStatus)
[ fc_monitor ] ---> /fc/status    (FlightStatus)      <- 依赖 MAVROS(/mavros/*)
[ lora_node ] ---> /lora/samples  (LoRaSamples)       <- 依赖 485 Modbus RTU
               ---> /lora/summary (LoRaSummary)
               srv /lora/query_node /lora/query_summary
                         │
                         ▼
              [ monitor_node ] ---> /monitor/device_alert (DeviceAlert)
                         │
                         ▼
              [ safety_node ] ---> /safety/status (SafetyStatus, safe_to_control)
                         │
                         ▼
              [ link_node ]   ---> 串口 (JSON 帧 → Qt上位机)
              [ cloud_node ]  ---> MQTT (JSON 帧 → 公有云)
```

## 5. 消息定义 (airship_msgs)

| 消息 | 来源 | 关键字段 |
|------|------|---------|
| `BmsStatus` | bms_node | pack_voltage / pack_current / soc / 单体电压/温度 / fault_word |
| `BackupBmsStatus` | backup_bms_node | pack_voltage / pack_current / soc / soh / 单体电压温度统计 / alarm_word / protect_word / fault_word / system_word |
| `MpptStatus` | mppt_node | pv_voltage / battery_voltage / charge_current / energy / fault_state |
| `DcdcStatus` | dcdc_node | input_voltage / output_voltage / output_current / output_power / fault_word |
| `FlightStatus` | fc_monitor | online / roll_pitch_yaw / lat_lon / vx_vy_vz / flight_mode / armed / battery |
| `LoRaSamples` | lora_node | samples: LoRaSample[](node_id / is_pressure / temp_celsius / pressure_pa / alarm) |
| `LoRaSummary` | lora_node | serial_online / node_count / online_count / alarm_count / avg_temp / max_temp / min_temp / alarm_node_ids |
| `SafetyStatus` | safety_node | safe_to_control / dcdc_ok / battery_ok / backup_battery_ok / reason |
| `DeviceAlert` | monitor_node | device_type / severity / code / message |

> **LoRa 服务**（airship_msgs 定义）：`/lora/query_node`（按节点 ID 查最新采样）、`/lora/query_summary`（主动触发一次汇总）。

## 6. 数传下传协议

link_node 将各设备状态聚合为**单行 JSON**,加帧头帧尾经串口下传:

```
帧格式:  0xAA 0x55 <JSON>\n

示例:
AA 55 {"t":1785928200.123,"bms":{"online":true,"pack_v":367.2,"pack_i":0.0,"soc":85,
"max_v":3.62,"min_v":3.58,"diff_v":0.04,"max_t":32.5,"alarm":0},"backup":{"online":true,
"pack_v":41.2,"pack_i":0.0,"soc":97,"soh":98,"max_v":3.50,"min_v":3.48,"diff_v":0.02,
"max_t":30.1,"alarm":0,"protect":0,"fault":0,"sys":64},"dcdc":{...},
"lora":{"nodes":[{"id":1,"online":1,"temp":25.4,"pressure":0,"alarm":0}]}}
```

- 离线设备(`online=false`)不出现在帧中
- `lora` 字段: 只要机载收到过一轮采样即出现, 节点全离线时为空数组 `"lora":{"nodes":[]}`
- `backup` 字段: 12S 备用电源 BMS, 仅在线(`online=true`)时出现
- 地面 Qt 上位机按帧头 `0xAA 0x55` 定位,解析 JSON
- 数传链路下传 BMS/备用电源/MPPT/DCDC/飞控FC/LoRa; 与 4G 上云链路数据集一致
- 完整字段定义见 [地面站对接协议](./lingyun01/地面站/地面站对接协议.md)

## 7. 安全监控

monitor_node 提供:
- **链路看门狗**: 设备超过 `link_timeout_s`(默认3s)未上报 → 判离线 → 发布 DeviceAlert
- **状态变化告警**: BMS 告警级别变化、MPPT 故障位、DCDC 总故障位、备用电源异常(alarm/protect/fault 字) 触发告警
- **启动防误报**: 未收到首个数据前不判离线(避免启动误报)

safety_node 提供:
- **安全仲裁**: 聚合 DCDC / 主 BMS / 12S 备用电源判据, 任一不满足即 `safe_to_control=false`(fail-safe)
- **备用电源判据**: 在线 且 总压 ≥ `backup_bms_min_voltage` 且 `fault_word==0`, 结果写入 `/safety/status.backup_battery_ok`
- **超时 fail-safe**: 判据超时(`backup_bms_timeout_s`)未收到数据视为不安全

## 9. 扩展规范

新增设备(如新的电源模块):
1. 厂家协议文件放入 `docs/lingyun01/<设备>/`
2. 在 `airship_msgs` 定义对应状态消息
3. 新建 `airship_<设备>` 驱动节点(参考 airship_dcdc 范式)
4. 在 monitor_node / link_node 中登记订阅与打包
5. 在 bringup launch 中注册节点

## 11. 飞控数据监控 (airship_fc)

通过 **MAVROS** 采集飞控(PX4 二次开发, 雷迅 X25 EVO, 网口 ETH/UDP)数据, 聚合为统一的 `FlightStatus` 发布到 `/fc/status`。

**MAVROS topic 映射:**

| MAVROS 话题 | 内容 | 输出字段 |
|------------|------|---------|
| `/mavros/state` | 连接/上锁/飞行模式 | online / armed / flight_mode |
| `/mavros/imu/data` | 四元数 | roll/pitch/yaw (四元数→欧拉角) |
| `/mavros/global_position/global` | GPS | lat / lon / alt_amsl |
| `/mavros/global_position/local` | 相对高度/速度(E N U) | alt_rel / vx / vy / vz |
| `/mavros/battery` | 电池 | voltage / current / remaining |

**online 判定**: 综合 MAVROS `connected` 标志 + 心跳看门狗(`fc_timeout_s`, 默认 2s)。

> 本节点仅**监控**, 不发送任何控制指令, 遵循"safety_status.safe_to_control 前不动作"约束。

## 12. 4G 上云 (airship_cloud / cloud_node)

订阅 `/bms/status`、`/mppt/status`、`/dcdc/status`、`/fc/status`、`/lora/samples`, 定时打包为 JSON, 经 **MQTT**(libmosquitto)上报公有云。

- **参数**: `mqtt_host` / `mqtt_port` / `mqtt_topic` / `mqtt_username` / `mqtt_password` / `tx_rate_hz`
- **当前状态**: `mqtt_host=localhost` 为占位, **Broker 地址待定**
- **安全约束**: 4G 链路仅上报, 不接收控制指令(详见 [03_双链路与4G远程监控架构](./03_双链路与4G远程监控架构.md))

## 13. LoRa 温度/压力采集 (airship_lora / lora_node)

通过 **USB-RS485 串口**以 **Modbus RTU** 轮询集中器, 采集多个 LoRa 节点的温度/压力。
协议解析为独立库 `airship_lora::modbus_rtu`(可 gtest), 串口复用 `airship_link::SerialInterface`。

**接口:**
| 类型 | 名称 | 内容 |
|------|------|------|
| 发布 | `/lora/samples` | `LoRaSamples` 每轮采集结果 |
| 发布 | `/lora/summary` | `LoRaSummary` 温度统计汇总 |
| 服务 | `/lora/query_node` | `QueryNode` 按节点 ID 查最新采样 |
| 服务 | `/lora/query_summary` | `QuerySummary` 主动触发一次汇总 |

**参数 (airship_params.yaml / 运行时):**
| 参数 | 默认 | 说明 |
|------|------|------|
| `serial_device` | `/dev/ttyUSB0` | 485 串口设备 |
| `baud_rate` | `9600` | Modbus RTU 波特率 |
| `slave_addr` | `1` | 集中器从机地址 |
| `node_ids` | `[1,2]` | LoRa 节点 ID 列表 |
| `node_types` | `["temperature","temperature"]` | 节点类型, `"temperature"`/`"pressure"`, 与 node_ids 一一对应 |
| `sample_period_ms` | `2000` | 采集周期, **动态参数**(运行中可改, 下限 100ms) |
| `temp_reg_addr` | `0x76C1` | 温度寄存器起始地址 |
| `pressure_reg_addr` | `0x8EF9` | 压力寄存器起始地址 |
| `alarm_low` / `alarm_high` | `-10` / `60` | 温度告警下限/上限(℃) |
| `resp_timeout_ms` | `200` | 单次读取响应超时 |
| `reconnect_ms` | `2000` | 串口掉线自动重连周期 |

**告警判定:** 温度节点 `temp < alarm_low` → `-1`(超下限), `temp > alarm_high` → `1`(超上限), 否则 `0`(正常)。

**可靠性与状态区分:**
- 单节点读取失败 → 该节点 `online=0`(节点离线)。
- **连续多轮全部节点失败** → 判定 485 串口掉线(区别于单节点离线), 进入自动重连; `LoRaSummary.serial_online` 用于区分串口掉线与节点离线。

> 该节点仅**采集上报**, 不做任何控制; 数据经数传(`link_node`)与 4G(`cloud_node`)两条链路上送。

## 14. 12S 备用电源 BMS (airship_backup_bms / backup_bms_node)

12S 备用锂电池 BMS 与主 BMS(CAN) 不同, 走**串口**(北辰协议 V1.4, 默认 9600 8N1)。
协议解析为独立库 `airship_backup_bms::backup_bms_protocol`(可 gtest), 串口复用 `airship_link::SerialInterface`。

**接口:**
| 类型 | 名称 | 内容 |
|------|------|------|
| 发布 | `/backup_bms/status` | `BackupBmsStatus` 每轮轮询结果 |

**轮询指令 (北辰协议):**
| 指令 | 内容 |
|------|------|
| `0x06` | 基本信息1: 总压/总电流/SOC/SOH/电压温度统计/告警/保护/故障/系统状态字 |
| `0x07` | 单节温度: 逐点温度(0.1℃ s16) |
| `0x08` | 单节电压: 逐节电压(1mV) |

**参数 (airship_params.yaml):**
| 参数 | 默认 | 说明 |
|------|------|------|
| `serial_device` | `/dev/airship_backup_bms` | 备用电源串口设备(udev 符号链接) |
| `baud_rate` | `9600` | 串口波特率 |
| `addr` | `255` (`0xFF`) | 从机地址 |
| `host` | `16` (`0x10`) | 主机(上位机)信息 |
| `sample_period_ms` | `1000` | 轮询周期 |
| `resp_timeout_ms` | `200` | 单次响应超时 |
| `reconnect_ms` | `2000` | 串口掉线自动重连周期 |

**可靠性与状态区分:**
- 单指令解析失败(CRC/地址/指令/长度校验) → 该轮该字段无更新。
- **连续多轮全部指令失败** → 判定串口掉线, 进入自动重连; 掉线时发布 `online=false`。
- 帧校验: 起始字节(0x56 请求 / 0x57 响应)、地址、主机、指令、长度、CRC16 全量校验, 并做单字节起始同步。

**接入链路:** monitor 看门狗/告警、link JSON 下传(`backup` 字段)、cloud 上云、safety 安全仲裁。

> 该节点仅**采集上报**, 不做任何控制; 具体协议细节见 [12S_ROS集成说明](./lingyun01/BMS/12S备用电源/12S_ROS集成说明.md)。
