# 灵云01号 设备监控架构

## 1. 系统概述

树莓派5 作为**机载数据中继节点**,通过 CAN 总线接收各电源设备数据,解析后统一经串口数传下传给地面 Qt 上位机。

```
┌──────────────────────────── 树莓派5 (伴飞电脑) ────────────────────────────┐
│                                                                            │
│  MPPT ──┐                                                                 │
│  BMS  ──┼── CAN (SocketCAN can0, 250kbps) ──► airship_* 节点 ──► link_node│
│  DCDC ──┘                                                                    │
│  飞控  ── telem2(UART) ──► MAVROS(PX4) ──► fc_monitor ──► /fc/status        │
│  4G   ──► cloud_node(MQTT) ──► 公有云(地址待定)                              │
│                                                                              │
│  设备驱动:  bms_node / mppt_node / dcdc_node                                 │
│  飞控监控:  fc_monitor_node (MAVROS 聚合)                                    │
│  状态聚合:  monitor_node (告警/日志/看门狗)                                  │
│  数传链路:  link_node (JSON打包, 串口下传)                                   │
│  4G 上云:   cloud_node (MQTT 汇总上报)                                       │
└──────────────────────────────────────────────────────────────────────────┘
                                                                              │
                                                             串口 (Linux 串口)
                                                                              ▼
                                                        地面 Qt 上位机 (解析显示)
```

## 2. 硬件与接口

| 项目 | 参数 |
|------|------|
| 主控 | Raspberry Pi 5 (8GB) |
| 系统 | Ubuntu 24.04 LTS + ROS2 Jazzy |
| CAN 接入 | USB-CAN 适配器 → SocketCAN `can0` |
| CAN 波特率 | 250 kbps (各设备一致) |
| CAN 帧类型 | 扩展帧 (29位 ID) |
| 数传 | 串口模块 (默认 /dev/ttyUSB0, 115200 baud) |
| 飞控 | 雷迅 X25 EVO, 二次开发 PX4, telem2 串口 (默认 /dev/ttyAMA1, 921600) |
| 4G 上云 | SIM7600G-H4G + MQTT(libmosquitto), Broker 地址待定 |

## 3. 软件包结构

```
src/
├── airship_msgs/        # 设备监控消息定义 (BmsStatus/MpptStatus/DcdcStatus/DeviceAlert/FlightStatus)
├── airship_can/         # SocketCAN 抽象层 (收发帧)
├── airship_utils/       # 可测工具库 (CAN解析/单位换算/限幅/四元数转欧拉角)
├── airship_bms/         # BMS 驱动节点
├── airship_mppt/        # MPPT 驱动节点
├── airship_dcdc/        # DCDC 驱动节点
├── airship_fc/          # 飞控数据监控节点 (MAVROS 聚合 -> /fc/status)
├── airship_cloud/       # 4G 上云节点 (MQTT 汇总上报)
├── airship_monitor/     # 设备监控聚合节点 (告警/看门狗)
├── airship_link/        # 串口数传链路节点 (JSON 下传)
└── airship_bringup/     # launch + 参数配置
```

## 4. 节点拓扑与话题

```
[ bms_node ]  ---> /bms/status    (BmsStatus)
[ mppt_node ] ---> /mppt/status   (MpptStatus)
[ dcdc_node ] ---> /dcdc/status   (DcdcStatus)
[ fc_monitor ] ---> /fc/status    (FlightStatus)      <- 依赖 MAVROS(/mavros/*)
                         │
                         ▼
              [ monitor_node ] ---> /monitor/device_alert (DeviceAlert)
                         │
                         ▼
              [ link_node ]   ---> 串口 (JSON 帧 → Qt上位机)
              [ cloud_node ]  ---> MQTT (JSON 帧 → 公有云)
```

## 5. 消息定义 (airship_msgs)

| 消息 | 来源 | 关键字段 |
|------|------|---------|
| `BmsStatus` | bms_node | pack_voltage / pack_current / soc / 单体电压/温度 / fault_word |
| `MpptStatus` | mppt_node | pv_voltage / battery_voltage / charge_current / energy / fault_state |
| `DcdcStatus` | dcdc_node | input_voltage / output_voltage / output_current / output_power / fault_word |
| `FlightStatus` | fc_monitor | online / roll_pitch_yaw / lat_lon / vx_vy_vz / flight_mode / armed / battery |
| `DeviceAlert` | monitor_node | device_type / severity / code / message |

## 6. 数传下传协议

link_node 将各设备状态聚合为**单行 JSON**,加帧头帧尾经串口下传:

```
帧格式:  0xAA 0x55 <JSON>\n

示例:
AA 55 {"t":1785928200.123,"bms":{"online":true,"pack_v":367.2,"pack_i":0.0,"soc":85,
"max_v":3.62,"min_v":3.58,"diff_v":0.04,"max_t":32.5,"alarm":0},"dcdc":{...}}
```

- 离线设备(`online=false`)不出现在帧中
- 地面 Qt 上位机按帧头 `0xAA 0x55` 定位,解析 JSON

## 7. 安全监控

monitor_node 提供:
- **链路看门狗**: 设备超过 `link_timeout_s`(默认3s)未上报 → 判离线 → 发布 DeviceAlert
- **状态变化告警**: BMS 告警级别变化、MPPT 故障位、DCDC 总故障位触发告警
- **启动防误报**: 未收到首个数据前不判离线(避免启动误报)

## 9. 扩展规范

新增设备(如新的电源模块):
1. 厂家协议文件放入 `docs/lingyun01/<设备>/`
2. 在 `airship_msgs` 定义对应状态消息
3. 新建 `airship_<设备>` 驱动节点(参考 airship_dcdc 范式)
4. 在 monitor_node / link_node 中登记订阅与打包
5. 在 bringup launch 中注册节点

## 10. 已知待完善

## 11. 飞控数据监控 (airship_fc)

通过 **MAVROS** 采集飞控(PX4 二次开发, 雷迅 X25 EVO, telem2 串口)数据, 聚合为统一的 `FlightStatus` 发布到 `/fc/status`。

**MAVROS topic 映射:**

| MAVROS 话题 | 内容 | 输出字段 |
|------------|------|---------|
| `/mavros/state` | 连接/上锁/飞行模式 | online / armed / flight_mode |
| `/mavros/imu/data` | 四元数 | roll/pitch/yaw (四元数→欧拉角) |
| `/mavros/global_position/global` | GPS | lat / lon / alt_amsl |
| `/mavros/global_position/local` | 相对高度/速度(E N U) | alt_rel / vx / vy / vz |
| `/mavros/battery` | 电池 | voltage / current / remaining |

**online 判定**: 综合 MAVROS `connected` 标志 + 心跳看门狗(`fc_timeout_s`, 默认 2s)。

> 本节点仅**监控**, 不发送任何控制指令, 遵循"safety_status.safe_to_control 前不动作"约束。

## 12. 4G 上云 (airship_cloud / cloud_node)

订阅 `/bms/status`、`/mppt/status`、`/dcdc/status`、`/fc/status`, 定时打包为 JSON, 经 **MQTT**(libmosquitto)上报公有云。

- **参数**: `mqtt_host` / `mqtt_port` / `mqtt_topic` / `mqtt_username` / `mqtt_password` / `tx_rate_hz`
- **当前状态**: `mqtt_host=localhost` 为占位, **Broker 地址待定**
- **安全约束**: 4G 链路仅上报, 不接收控制指令(详见 [03_双链路与4G远程监控架构](./03_双链路与4G远程监控架构.md))
