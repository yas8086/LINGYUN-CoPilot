## 1. 环境准备

每次打开新终端，先加载 ROS2 环境和工作空间：

```bash
source /opt/ros/jazzy/setup.bash      # 加载 ROS2 基础环境
```

## 2. 命令行工具 `ros2` 详解

### 2.1 节点相关

```bash
ros2 node list                    # 列出所有运行中的节点
ros2 node info /bms_node          # 查看节点详情(订阅/发布/服务/参数)
ros2 node list | grep bms         # 过滤
```

### 2.2 话题相关（最常用）

```bash
ros2 topic list                   # 列出所有话题
ros2 topic list -t               # 连同话题类型一起列出
ros2 topic echo /bms/status      # 实时打印消息内容
ros2 topic info /bms/status      # 查看发布者/订阅者数量
ros2 topic hz /bms/status        # 统计发布频率(Hz)
ros2 topic bw /bms/status        # 统计带宽
ros2 topic type /bms/status      # 查看话题消息类型
```

**针对本项目实战**：启动后想看 BMS 是否正常上报：

```bash
ros2 launch airship_bringup device_monitor.launch.py
# 新终端
ros2 topic list                          # 应看到 /bms/status /mppt/status /dcdc/status
ros2 topic echo /bms/status              # 实时看电压/SOC
ros2 topic hz /bms/status                # 应接近设备上报频率
ros2 topic info /bms/status              # 确认有订阅者(monitor_node)
```

### 2.3 服务相关

```bash
ros2 service list                 # 列出所有服务
ros2 service type <服务名>         # 查看服务类型
ros2 service call <服务名> <类型> "{参数}"   # 调用服务
```

### 2.4 参数相关

```bash
ros2 param list                   # 列出某节点的参数
ros2 param get /bms_node can_interface   # 读取参数
ros2 param set /bms_node cell_count 102  # 运行中修改参数
ros2 param dump /bms_node        # 导出成 yaml
```

### 2.5 运行与日志

```bash
ros2 run <包名> <可执行文件>                     # 运行节点
ros2 run <包名> <可执行文件> --ros-args -p 参数:=值  # 带参数运行
ros2 log list /bms_node             # 查看节点日志级别
ros2 log set /bms_node DEBUG        # 运行中改日志级别
```

### 2.6 接口与包

```bash
ros2 interface show airship_msgs/msg/BmsStatus   # 查看消息字段定义
ros2 interface list                             # 列出所有接口
ros2 pkg list                                    # 列出已安装的所有包
ros2 pkg prefix airship_bms                      # 查看包的安装路径
```

## 3. 构建工具 colcon

### 3.1 常用命令

```bash
colcon build                          # 编译所有包
colcon build --packages-select airship_bms       # 只编译指定包
colcon build --packages-up-to airship_bms        # 编译该包及其依赖
colcon build --symlink-install       # python/launch 改动即时生效
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release   # 传 CMake 参数
colcon build --parallel-workers 4    # 并行编译
colcon build --event-handlers console_direct+      # 实时显示编译输出
```

### 3.2 项目场景

设备监控阶段经常只改一个包，用增量编译省时间：

```bash
colcon build --packages-select airship_bms && source install/setup.bash
```

### 3.3 常用小技巧

```bash
colcon test                          # 运行所有测试(模块5)
colcon test-result --verbose         # 查看测试结果
colcon clean                         # 清理 build/install
rm -rf build install log            # 彻底清理(重新全量编译)
```

## 4. 可视化工具

### 4.1 rviz2 —— 3D 可视化

```bash
rviz2
```

- **TF** 显示：看坐标系树和坐标轴
- **Image / PointCloud / LaserScan**：看传感器数据
- **RobotModel**：看机器人模型
- 适合验证数据在正确坐标系下的位置

> 本项目设备监控阶段数据是标量（电压/电流/温度），rviz 用处不大；进入飞控阶段后，rviz 是看位姿、轨迹、坐标系的核心工具。

### 4.2 rqt —— ROS 图形化工具集

```bash
rqt_graph          # 可视化节点/话题关系图(最常用!)
rqt_console        # 查看所有节点的日志(按级别过滤)
rqt_plot           # 实时曲线绘图
rqt_topic          # 订阅查看话题
```

**`rqt_graph` 特别有用**：一图看清"谁发布、谁订阅"，是排查通信问题的第一利器。

```bash
rqt_graph
```

> 项目实战：启动设备监控后打开 `rqt_graph`，能直观看到 `bms_node / mppt_node / dcdc_node → monitor_node → link_node` 的数据流。

## 5. 日志与调试

### 5.1 日志级别

ROS2 日志级别（从低到高）：

```
DEBUG < INFO < WARN < ERROR < FATAL
```

- 默认只显示 INFO 及以上的日志
- 需要看调试信息时：
  ```bash
  ros2 run airship_bms bms_node --ros-args --log-level debug
  ```

### 5.2 在代码里控制日志级别

```cpp
RCLCPP_DEBUG(this->get_logger(), "收到 CAN 帧 id=0x%x", frame.id);
```

### 5.3 常见调试手段

| 问题 | 手段 |
|------|------|
| 节点没收到消息 | `ros2 topic echo` + `ros2 topic info` 看是否有订阅者 |
| 发布频率异常 | `ros2 topic hz` |
| 消息类型不匹配 | `ros2 topic info -t` 对比类型 |
| 找不到包/可执行文件 | 确认 `source install/setup.bash` 是否执行 |
| C++ 崩溃/段错误 | 用 gdb |
| 死活不发布 | 检查 QoS 是否兼容 |

### 5.4 gdb 调试 C++ 节点

```bash
# 需要 debug 版编译
colcon build --packages-select airship_bms --cmake-args -DCMAKE_BUILD_TYPE=Debug

# 用 gdb 启动
gdb --args ros2 run airship_bms bms_node
# 进入 gdb 后: run / break 行号 / bt(查看调用栈)
```

## 6. 包管理与依赖

### 6.1 rosdep —— 自动安装依赖

```bash
rosdep update                                # 更新索引
rosdep install --from-paths src -y -i        # 安装 src/ 下所有包缺失的依赖
```

根据 `package.xml` 里的 `<depend>` 自动安装系统依赖，省去手动 `apt install`。

### 6.2 手动安装常用包

```bash
sudo apt install ros-jazzy-tf2-ros
sudo apt install ros-jazzy-rviz2
sudo apt install ros-jazzy-rqt-graph
```

## 7. 一个完整的调试实战流程（针对本项目）

假设你启动设备监控后，`monitor_node` 一直报"设备离线"。按工具链思路排查：

```bash
# ① 启动
ros2 launch airship_bringup device_monitor.launch.py

# ② 看节点是否都在
ros2 node list

# ③ 看话题是否在发布
ros2 topic list
ros2 topic hz /bms/status        # 如果 0Hz → BMS 没收到 CAN 数据

# ④ 如果 CAN 问题: 检查 CAN 接口
candump can0                     # 看能否收到原始 CAN 帧
ip link show can0                # 看 CAN 接口状态

# ⑤ 看 monitor 的看门狗逻辑
ros2 topic echo /monitor/device_alert   # 看告警内容(含超时时间)

# ⑥ 可视化通信结构
rqt_graph
```

这套"**节点 → 话题 → 底层 → 告警 → 视图**"的排查顺序，覆盖了工具链的绝大部分能力。
