## 0. 本模块要解决什么问题

模块 1 讲了 ROS2 的**通信概念**（节点、话题、服务…）。但一个真正的工程，不只是写节点代码，还要解决：

- 代码怎么**组织**成一个个可独立编译、可复用的单元？→ **包 Package**
- 一个包要依赖哪些库，怎么声明？→ **package.xml**
- 怎么把 C++ 源码**编译**成可执行文件并安装？→ **CMakeLists.txt**
- 怎么**一键启动**多个节点？→ **launch 文件**
- 节点的参数怎么**集中管理**、不用改代码？→ **yaml 参数文件**
- 整个工程怎么**构建**？→ **colcon**

这些合起来就是"工程化配置"。本模块用你项目里的真实文件逐一讲解。

## 1. 工作空间 Workspace

一个 ROS2 工程的最上层叫**工作空间（workspace）**，通常包含 4 个目录：

```
LINGYUN-CoPilot/            ← 工作空间根目录
├── src/                     ← 源码目录：所有包都在这里
│   ├── airship_bms/         ← 一个包
│   ├── airship_mppt/
│   ├── airship_bringup/
│   └── ...
├── build/                   ← 编译中间产物(由 colcon 生成, 可删)
├── install/                 ← 安装产物(可执行文件、库、launch 等)
└── log/                     ← 构建日志
```

- **`src/`**：你写代码的地方，放所有包。
- **`build/`、`install/`、`log/`**：由 `colcon build` 自动生成，属于编译产物，**一般加入 `.gitignore`**，不提交到 Git。

> 你的项目当前只有 `src/`，因为还没执行过 `colcon build`（或构建产物被清理了）。

## 2. 包 Package —— 代码组织的基本单元

**包（package）** 是 ROS2 代码组织、编译、分发的最小单元。一个包至少包含两个文件：

```
airship_bms/
├── package.xml        # 包元数据 + 依赖声明
├── CMakeLists.txt     # 编译规则 (C++ 包)
└── src/
    └── bms_node.cpp   # 源码
```

ROS2 包分两种**构建类型（build_type）**：
- **`ament_cmake`**：C++ 包，用 CMake 构建。你的所有包都是这种。
- **`ament_python`**：Python 包，用 `setup.py` 构建。

包类型在 `package.xml` 的 `<export>` 里声明（见下）。

### 包与模块1概念的对应

模块 1 说"节点是进程里的一个单元"，而**包是编译单元**。一个包可以编译出多个可执行文件（多个节点）。你项目里几乎每个包编译出 1 个节点，`airship_link` 还额外编译出测试程序。

## 3. package.xml —— 包元数据与依赖声明

看你的 [airship_bms/package.xml](file:///home/lingyun01/LINGYUN-CoPilot/src/airship_bms/package.xml)：

```xml
<?xml version="1.0"?>
<package format="3">
  <name>airship_bms</name>              <!-- 包名 -->
  <version>0.1.0</version>              <!-- 版本 -->
  <description>锂电池 BMS 驱动节点...</description>
  <maintainer email="dev@lingyun.local">Lingyun Airship Team</maintainer>
  <license>Proprietary</license>        <!-- 闭源协议 -->

  <buildtool_depend>ament_cmake</buildtool_depend>   <!-- 构建工具 -->

  <!-- 运行时与编译时都需要的依赖 -->
  <depend>rclcpp</depend>
  <depend>std_msgs</depend>
  <depend>airship_msgs</depend>
  <depend>airship_can</depend>
  <depend>airship_utils</depend>

  <export>
    <build_type>ament_cmake</build_type>   <!-- 声明包类型 -->
  </export>
</package>
```

### 关键元素

| 元素 | 作用 |
|------|------|
| `<name>` | 包名，**必须与目录名一致** |
| `<depend>` | 编译 + 运行时依赖（最常用） |
| `<buildtool_depend>` | 构建工具依赖（如 `ament_cmake`） |
| `<build_depend>` | 仅编译时需要 |
| `<exec_depend>` | 仅运行时需要 |
| `<test_depend>` | 仅测试时需要 |
| `<export><build_type>` | 声明是 cmake 还是 python 包 |

### 依赖声明的意义

写 `package.xml` 不是走形式，它决定了：
1. **构建顺序**：`colcon` 会分析依赖，自动按 DAG 顺序先编译 `airship_msgs`、`airship_can`、`airship_utils`，再编译 `airship_bms`。
2. **运行时查找**：`ros2 run`、launch 能通过包名找到可执行文件，靠的就是这个元数据。

> **依赖方向检查**：`airship_bms` 依赖 `airship_msgs`，但 `airship_msgs` **不能**依赖 `airship_bms`，否则循环依赖会报错。这正是你项目坚持"消息独立成一个包"的原因。

## 4. CMakeLists.txt —— 编译规则详解

看你的 [airship_bms/CMakeLists.txt](file:///home/lingyun01/LINGYUN-CoPilot/src/airship_bms/CMakeLists.txt)：

```cmake
cmake_minimum_required(VERSION 3.8)
project(airship_bms)                     # 工程名, 需与包名一致

# 开启警告
if(CMAKE_COMPILER_IS_GNUCXX OR CMAKE_CXX_COMPILER_ID MATCHES "Clang")
  add_compile_options(-Wall -Wextra -Wpedantic)
endif()

# 查找依赖包
find_package(ament_cmake REQUIRED)
find_package(rclcpp REQUIRED)
find_package(std_msgs REQUIRED)
find_package(airship_msgs REQUIRED)
find_package(airship_can REQUIRED)
find_package(airship_utils REQUIRED)

# 编译可执行文件
add_executable(bms_node src/bms_node.cpp)
target_compile_features(bms_node PUBLIC cxx_std_17)   # 指定 C++17
ament_target_dependencies(bms_node
  rclcpp std_msgs airship_msgs airship_can airship_utils)  # 链接依赖

# 安装到 lib/<包名>/ 目录
install(TARGETS bms_node
  DESTINATION lib/${PROJECT_NAME})

# 测试与 lint
if(BUILD_TESTING)
  find_package(ament_lint_auto REQUIRED)
  set(ament_cmake_copyright_FOUND TRUE)  # 闭源, 跳过版权检查
  ament_lint_auto_find_test_dependencies()
endif()

ament_package()                          # 收尾, 必须最后
```

### 逐段理解

**① `find_package`** —— 找到这个包所需要的库。每个被 `#include` 的包都要在这里 `find_package`，**并且在 package.xml 里也要声明**。两者必须一致，否则会报错。

**② `add_executable`** —— 把 `src/bms_node.cpp` 编译成可执行文件 `bms_node`。

```cmake
add_executable(bms_node src/bms_node.cpp)
```

**③ `ament_target_dependencies`** —— 这是 ROS2 的 CMake 封装，等于一次帮你把每个依赖的**头文件路径 + 库 + 编译选项**都链接好。比手写 `target_link_libraries` 省事得多。

```cmake
ament_target_dependencies(bms_node
  rclcpp std_msgs airship_msgs airship_can airship_utils)
```

**④ `install(TARGETS ...)`** —— 把编译好的可执行文件**安装**到 `install/lib/airship_bms/`。这一步**必不可少**——不安装的话，`ros2 run` 和 launch 都找不到这个程序。

```cmake
install(TARGETS bms_node
  DESTINATION lib/${PROJECT_NAME})
```

**⑤ `ament_package()`** —— 必须放在文件末尾，负责生成包相关的元数据、注册包。

### 消息包的特殊 CMakeLists（重点）

看你的 [airship_msgs/CMakeLists.txt](file:///home/lingyun01/LINGYUN-CoPilot/src/airship_msgs/CMakeLists.txt)，它和普通节点包不一样：

```cmake
find_package(ament_cmake REQUIRED)
find_package(rosidl_default_generators REQUIRED)   # 消息代码生成器
find_package(std_msgs REQUIRED)
find_package(builtin_interfaces REQUIRED)

set(msg_files
  "msg/BmsStatus.msg"
  "msg/MpptStatus.msg"
  "msg/DcdcStatus.msg"
  "msg/DeviceAlert.msg"
)

# 关键: 从 .msg 文件生成 C++/Python 接口代码
rosidl_generate_interfaces(${PROJECT_NAME}
  ${msg_files}
  DEPENDENCIES std_msgs builtin_interfaces
  ADD_LINTER_TESTS
)
```

**`rosidl_generate_interfaces`** 是消息包的灵魂：它读取 `.msg`（以及 `.srv`/`.action`）文件，自动生成 C++ 头文件（`airship_msgs/msg/bms_status.hpp`）和 Python 模块。你代码里 `#include "airship_msgs/msg/bms_status.hpp"` 就是它生成的。

> 这就是模块 1 里 `airship_msgs::msg::BmsStatus` 这个 C++ 类从哪来的——**编译时自动生成**，不需要你手写。

## 5. launch 文件 —— 一键启动多个节点

launch 文件用来**编排**：一次启动多个节点、设置参数、配置命名空间。推荐用 Python 写的 `.launch.py`。

看你的 [device_monitor.launch.py](file:///home/lingyun01/LINGYUN-CoPilot/src/airship_bringup/launch/device_monitor.launch.py)：

```python
from ament_index_python.packages import get_package_share_directory
from launch import LaunchDescription
from launch_ros.actions import Node

def generate_launch_description():
    # 找到 airship_bringup 包的安装目录
    bringup_share_dir = get_package_share_directory('airship_bringup')
    # 组合出参数文件路径
    params_file = os.path.join(bringup_share_dir, 'config', 'airship_params.yaml')

    # 定义一个节点
    bms_node = Node(
        package='airship_bms',        # 包名
        executable='bms_node',        # CMakeLists 里 add_executable 的名字
        name='bms_node',              # 覆盖节点名
        parameters=[params_file],     # 从 yaml 加载参数
        output='screen',              # 日志输出到终端
    )

    # ... mppt_node / dcdc_node / monitor_node / link_node 类似 ...

    # 把所有节点装进 LaunchDescription 返回
    return LaunchDescription([bms_node, mppt_node, dcdc_node, monitor_node, link_node])
```

### 关键点

- **入口函数固定叫 `generate_launch_description()`**，launch 系统会调用它，返回 `LaunchDescription`。
- **`get_package_share_directory('包名')`**：拿到包的**安装目录**（`install/airship_bringup/`），这样才能找到随包安装的配置文件。
- **每个 `Node(...)`** 描述一个要启动的节点，字段 `package` + `executable` 对应 CMakeLists 的 `add_executable` 名字。
- **`parameters=[params_file]`**：把 yaml 参数文件一次性传给节点。

### 启动方式

```bash
ros2 launch airship_bringup device_monitor.launch.py
```

### 三种 launch 格式（了解）

| 格式 | 后缀 | 说明 |
|------|------|------|
| Python | `.launch.py` | 最灵活，官方推荐，你项目用这种 |
| XML | `.launch.xml` | 声明式，简单场景 |
| YAML | `.launch.yaml` | 声明式，简洁 |

## 6. 参数文件 yaml —— 集中管理参数

launch 里 `parameters=[params_file]` 指向的 yaml，就是参数的**集中配置文件**。看你的 [airship_params.yaml](file:///home/lingyun01/LINGYUN-CoPilot/src/airship_bringup/config/airship_params.yaml)：

```yaml
# 按节点名分组
bms_node:
  ros__parameters:
    can_interface: "can0"     # CAN 接口名
    cell_count: 102           # 电池单体串数

mppt_node:
  ros__parameters:
    can_interface: "can0"
    query_rate_hz: 1.0
    device_addr: 1

dcdc_node:
  ros__parameters:
    can_interface: "can0"
    control_rate_hz: 5.0
    set_voltage: 48.0
    set_current: 80.0
    dcdc_enabled: true

monitor_node:
  ros__parameters:
    watchdog_rate_hz: 1.0     # 看门狗频率
    link_timeout_s: 3.0       # 离线超时

link_node:
  ros__parameters:
    serial_device: "/dev/ttyUSB0"
    baud_rate: 115200
    tx_rate_hz: 5.0
```

### 结构规则

```
节点名:
  ros__parameters:
    参数名: 值
```

- **顶层是节点名**：必须与 launch 里 `Node(name=...)` 或节点 `rclcpp::Node("xxx")` 的名字一致。
- **`ros__parameters:`** 是固定关键字，声明下面是这个节点的参数。
- 每个参数名要和代码里 `declare_parameter("can_interface", ...)` 的名字**完全一致**。

### yaml 参数如何进入节点

流程：
1. launch 读 `airship_params.yaml`
2. 找到 `bms_node:` 段
3. 以 `--ros-args -p can_interface:=can0 -p cell_count:=102` 的方式传给 `bms_node` 节点
4. 节点里 `declare_parameter("can_interface", "can0")` 时，发现 yaml 已有值，就用 yaml 的值覆盖默认值

**好处**：调 CAN 接口、改波特率、改超时…**只改 yaml，不用改代码、不用重新编译**。

> **参数类型要匹配**：yaml 里 `cell_count: 102` 是整数，代码里 `declare_parameter("cell_count", 0)` 默认值是整数，类型一致才行。`dcdc_enabled: true` 是布尔，`declare_parameter("dcdc_enabled", false)` 也是布尔。类型不一致会报错。

## 7. 完整构建流程 colcon

模块 1-2 讲的所有文件，最后靠 **colcon** 串起来编译。

### 7.1 首次构建

```bash
cd <工作空间根目录>     # 例: cd ~/dev_ws
colcon build            # 编译 src/ 下所有包
```

### 7.2 常用选项

```bash
colcon build --packages-select airship_bms         # 只编译指定包
colcon build --packages-up-to airship_bms          # 编译该包及其依赖
colcon build --symlink-install                     # 源码改动即时生效(python/launch)
colcon build --cmake-args -DCMAKE_BUILD_TYPE=Release   # 传 CMake 参数
colcon build --parallel-workers 4                  # 并行
```

### 7.3 必须 source 环境

编译完，要让终端找到新生成的包，需要加载环境：

```bash
source install/setup.bash
```

**每次编译出新包后，都要重新 `source`**，否则 `ros2 run` 找不到。这是新手最常见的困惑。

### 7.4 完整验证流程

```bash
source install/setup.bash
ros2 run airship_bms bms_node                 # 单独跑一个节点
ros2 launch airship_bringup device_monitor.launch.py   # 一键启动全部
```

## 8. 命名空间 Namespace（概念）

当多个设备/节点需要隔离时，用**命名空间**。比如有"主电源"和"备份电源"两套 BMS，可以：

```python
Node(
    package='airship_bms',
    executable='bms_node',
    name='bms_node',
    namespace='main',       # 命名空间
)
```

这样话题变成 `main/bms/status`，与 `backup/bms/status` 隔离，互不干扰。launch 里 `Node()` 支持 `namespace=` 参数。

## 9. 工程化配置小结

一个 ROS2 工程的"配置骨架"是：

```
工作空间/
├── src/
│   └── 包名/
│       ├── package.xml        # 元数据 + 依赖
│       ├── CMakeLists.txt     # 编译规则
│       ├── src/               # 源码
│       ├── include/           # 头文件
│       ├── launch/            # (放bringup)启动文件
│       └── test/              # 测试代码(模块5)
├── build/  install/  log/     # colcon 产物
```

**对应关系速查**：

| 关注点 | 配置文件 | 你的项目文件 |
|--------|---------|-------------|
| 包元数据/依赖 | `package.xml` | `airship_bms/package.xml` |
| 编译规则 | `CMakeLists.txt` | `airship_bms/CMakeLists.txt` |
| 消息生成 | `rosidl_generate_interfaces` | `airship_msgs/CMakeLists.txt` |
| 启动编排 | `.launch.py` | `device_monitor.launch.py` |
| 参数集中管理 | `.yaml` | `airship_params.yaml` |
| 构建 | colcon | — |
