## 0. 一句话理解 TF

**TF（Transform，坐标变换）** 是 ROS 用来描述**坐标系之间相对位置和姿态**的机制。它解决一个问题：

> 我是机器人，我身上有 IMU、GPS、摄像头、轮子……它们各自测得的数据，到底是在"哪个坐标系、"里、相对"哪个坐标系"的？

TF 把这些坐标系组织成一棵树（TF Tree），让任何数据都能**换算到任意坐标系**下。

---

## 1. 为什么需要 TF？

嵌入式机器人有**多个传感器，每个传感器有自己的坐标系**：

```
[GPS]  → 经纬度 (GPS/世界坐标系)
[IMU]  → 加速度/姿态 (以自身为原点)
[摄像头] → 障碍物 (以相机为原点)
[飞艇]  → 机体坐标系 (机头方向为前)
```

问题：摄像头看到一个障碍物在"前方 2 米"，但这个"前方"是**相对摄像头**的。要让它变成"相对飞艇"或"相对世界"，就需要知道**摄像头相对飞艇的姿态**。这就是 TF 干的事。

**TF 的价值**：只要维护好坐标系之间的关系，任何节点都能用 `lookupTransform` 把数据从任意坐标系换算到任意坐标系，**不用自己写转换代码**。

## 2. TF2 基础概念

ROS2 用的是 **TF2**（第二代）。

### 2.1 frame_id —— 坐标系的名字

记住模块 1 里 `Header` 有一个字段 `frame_id`。它就是**坐标系的名字**。

```cpp
msg.header.frame_id = "body";   // 这条数据是在 "body" 坐标系下测的
```

**每一条带 Header 的位置/朝向数据，都必须声明它属于哪个 frame**，否则接收方不知道它在哪个坐标系。

### 2.2 变换 Transform —— 相对关系

一个变换描述：**frame A 相对 frame B 的平移 + 旋转**。

```cpp
// body 相对 world 的变换
transform.translation.x = 1.0;   // 平移
transform.rotation.x = 0.0;      // 旋转(四元数)
```

### 2.3 TF 树 TF Tree

坐标系之间是**父子关系**，所有坐标系共同构成一棵树（不能有环）：

```
world (根)
└── gps / ENU
    └── body (飞艇机体)
        ├── imu
        └── camera
```

- **每个坐标系只有一个父系**，但可以有多个子系。
- 从 `body` 到 `world` 的变换，可以通过沿树往上走逐级合成。

### 2.4 静态 TF vs 动态 TF

| 类型 | 特点 | 适用 |
|------|------|------|
| **静态 Static TF** | 固定不变 | 传感器固定在机体上（如 cam→body）、world→map |
| **动态 Dynamic TF** | 随时间变化 | 机体在世界中的位姿（body→world） |

## 3. 坐标变换的数学基础

### 3.1 平移 + 旋转

一个点 `p` 从坐标系 A 换算到坐标系 B：

```
p_B = R * p_A + t
```

其中：
- `R`：从 A 到 B 的**旋转矩阵**（3×3）
- `t`：从 A 到 B 的**平移向量**（A 的原点在 B 中的位置）

### 3.2 旋转的表示方式

| 表示 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| **欧拉角 (roll/pitch/yaw)** | 绕 x/y/z 轴旋转 | 直观 | 有"万向锁"问题，顺序敏感 |
| **四元数 (quaternion)** | (x,y,z,w) 四维 | 无万向锁，插值稳定 | 不直观，需计算 |
| **旋转矩阵 R** | 3×3 正交矩阵 | 计算方便 | 冗余(9个数) |

**TF2 底层用四元数**，但你在 rviz/命令行看的通常是欧拉角。

### 3.3 欧拉角转四元数（yaw 为例）

绕 Z 轴旋转 yaw 角对应的四元数：

```
x = 0
y = 0
z = sin(yaw / 2)
w = cos(yaw / 2)
```

### 3.4 逆变换

从 A→B 的变换求 B→A 的变换：旋转取**转置**，平移取**负的旋转矩阵乘平移**。

```
R_inv = R^T
t_inv = -R^T * t
```

## 4. 常用坐标系：ENU 与 NED（与本项目强相关）

这是模块 3 里**和你项目最相关**的部分。你的工程记忆里提到飞控阶段要做 **ENU↔NED** 转换。

### 4.1 ENU（东北上）—— 测绘/ROS2 默认

- **E**ast（东）+X
- **N**orth（北）+Y
- **U**p（上）+Z

ROS2 / Gazebo / 很多机器人框架默认用 ENU。

### 4.2 NED（北东地）—— 航空/飞控常用

- **N**orth（北）+X
- **E**ast（东）+Y
- **D**own（下）+Z

PX4、ArduPilot 等飞控固件默认用 NED。

### 4.3 两者的关系

对比可得：

| 轴 | ENU | NED |
|----|-----|-----|
| X | 东 East | 北 North |
| Y | 北 North | 东 East |
| Z | 上 Up | 下 Down |

**转换规则**：
- Z 轴：Up ↔ Down，**取反**
- X/Y 轴：**交换**（东和北对调）

转换矩阵（NED → ENU）：

```
[ x_ENU ]   [ 0  1  0 ] [ x_NED ]
[ y_ENU ] = [ 1  0  0 ] [ y_NED ]
[ z_ENU ]   [ 0  0 -1 ] [ z_NED ]
```

**为什么必须转换**：你的飞控（PX4）用 NED，而 ROS2 导航/可视化用 ENU。如果直接混用，yaw 方向会错 90°，上下会反——**这是飞控集成最常见的 bug**。

> 这也是为什么你项目记忆里强调"坐标转换要抽成 airship_utils 的纯函数并加单元测试"——转换错了，飞艇会飞错方向。

## 5. yaw 角的进一步说明（与你的 math_utils 相关）

你的 `airship_utils/math_utils.hpp` 里有：

```cpp
// 角度差,归一化到 [-pi, pi]
float angle_diff(float target, float current);

// 角度归一化到 [-pi, pi]
float normalize_angle(float angle);
```

这些角度工具是飞控/姿态控制的基础。yaw 角在 ENU 和 NED 下：

- **ENU**：yaw=0 指向东（+X）
- **NED**：yaw=0 指向北（+X）

加上上面矩阵的 X/Y 交换和 Z 取反，**yaw 的换算不是简单加减**，而是包含符号翻转。这就是为什么需要 `normalize_angle` 这类工具来保证角度始终落在 `[-π, π]`。

## 6. TF2 实践：发布静态 TF

### 6.1 用命令发布静态 TF（最简单）

```bash
# 发布 body 相对 world 的静态变换: 平移(1,0,0) 绕Z转90°
ros2 run tf2_ros static_transform_publisher \
  --x 1 --y 0 --z 0 --yaw 1.5707 --pitch 0 --roll 0 \
  --frame-id world --child-frame-id body
```

### 6.2 在 C++ 里发布静态 TF

```cpp
#include "tf2_ros/static_transform_broadcaster.h"
#include "geometry_msgs/msg/transform_stamped.hpp"

// 在节点里
auto broadcaster = std::make_shared<tf2_ros::StaticTransformBroadcaster>(this);

geometry_msgs::msg::TransformStamped t;
t.header.stamp = this->now();
t.header.frame_id = "world";           // 父坐标系
t.child_frame_id = "body";             // 子坐标系
t.transform.translation.x = 1.0;
t.transform.translation.y = 0.0;
t.transform.translation.z = 0.0;
t.transform.rotation.x = 0.0;          // 用四元数表示旋转
t.transform.rotation.y = 0.0;
t.transform.rotation.z = 0.7071;       // 90° 绕 Z
t.transform.rotation.w = 0.7071;

broadcaster->sendTransform(t);
```

### 6.3 发布动态 TF（机体在世界中的位姿）

```cpp
#include "tf2_ros/transform_broadcaster.h"
// 每个周期更新并广播 body 相对 world 的位姿
// (通常来自 IMU+GPS 融合的位姿估计)
```

## 7. 监听 TF：lookupTransform

**监听（Listen）** 是从 TF 树里查询两个坐标系之间的变换。

```cpp
#include "tf2_ros/buffer.h"
#include "tf2_ros/transform_listener.h"

// 在节点里
tf_buffer_ = std::make_shared<tf2_ros::Buffer>(this->get_clock());
tf_listener_ = std::make_shared<tf2_ros::TransformListener>(*tf_buffer_);

// 查询 camera 相对 body 的变换
try {
  auto tf = tf_buffer_->lookupTransform("body", "camera", tf2::TimePointZero);
  // tf.transform 就是 camera 在 body 坐标系下的位姿
} catch (const tf2::TransformException & e) {
  RCLCPP_WARN(this->get_logger(), "TF 查询失败: %s", e.what());
}
```

**`lookupTransform(target, source, time)`**：
- `target`：目标坐标系
- `source`：源坐标系
- 返回值：source 坐标系在 target 坐标系下的变换

注意要 `try-catch`——如果两个坐标系不在同一棵树上，会抛异常。

### 把点从 sensor 换算到 body

```cpp
#include "tf2_geometry_msgs/tf2_geometry_msgs.hpp"

geometry_msgs::msg::PointStamped sensor_point;
sensor_point.header.frame_id = "camera";   // 原始点在 camera 坐标系
sensor_point.point.x = 0.5; ...

geometry_msgs::msg::PointStamped body_point;
tf_buffer_->transform(sensor_point, body_point, "body");   // 换算到 body
```

## 9. 用 rviz 可视化 TF

TF 最有价值的地方之一就是**可视化**：

```bash
rviz2
```

- 添加 **TF** 显示插件，能看到整个 TF 树和坐标系坐标轴
- 添加 **Image / PointCloud** 等，能看到各传感器数据在正确坐标系下的位置
- 数据错位时，一眼就能看出是哪个坐标系没配好

命令行工具：

```bash
ros2 run tf2_ros tf2_echo world body      # 打印 world→body 的变换
ros2 run tf2_tools view_frames            # 生成 TF 树 PDF
```

## 10. TF 树设计与常见错误

### 10.1 设计原则

- **根坐标系**：通常选一个世界或地图坐标系（`world` / `map`）
- **一个父系多个子系**：机体（body）下挂所有传感器
- **静态关系**用 Static TF，**动态关系**（机体位姿）用动态 TF

### 10.2 常见错误

| 错误 | 现象 | 解决 |
|------|------|------|
| **frame_id 写错** | 数据在错误位置 | 检查每条消息的 frame_id |
| **坐标系不在同一棵树** | lookupTransform 抛异常 | 检查 TF 树是否连通 |
| **缺少 TF** | 收到 "No transform available" | 确认发布了该静态/动态 TF |
| **时间戳不匹配** | "frame is out of date" | 检查时间源是否一致 |
| **EUAL/NED 混用** | 方向偏 90°/上下反 | 用 4.3 的转换矩阵 |
| **欧拉角顺序错** | 姿态错乱 | 明确 roll-pitch-yaw 顺序 |

## 11. 与本项目的结合点

你的项目当前是**设备监控阶段**（BMS/MPPT/DCDC），这些设备数据（电压、电流、温度）**不涉及坐标系**，所以暂时用不到 TF。

TF 会在**飞控集成的下一阶段**派上用场：

| 场景 | 需要的 TF |
|------|-----------|
| 飞控(PX4, NED) 与 ROS2(ENU) 数据对接 | ENU↔NED 转换 |
| 把 GPS/IMU 数据统一到世界坐标系 | world → body |
| 传感器原始数据可视化 | 各传感器 → body |

到那时，建议把 ENU↔NED 转换实现为 `airship_utils` 里的纯函数（如 `enu_to_ned()`），配 gtest 单元测试，避免"大概转一下"带来的飞控安全隐患——这正是你项目记忆里的工程约束。

## 12. 小练习

1. **概念**：TF 解决什么问题？`frame_id` 在消息里起什么作用？
2. **树结构**：TF 树为什么不能有环？一个坐标系能有几个父系？几个子系？
