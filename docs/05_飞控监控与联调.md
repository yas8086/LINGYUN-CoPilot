# 飞控监控与联调记录

> 本文档记录伴飞电脑连接飞控(CUAV X25 EVO / PX4)的**联调实践经验**与**故障排查**。
> 属于本机开发文档, 与 [PX4 对接文档](./lingyun01/PX4飞控对接文档/07_实时监控协议对接文档.md) 互补:
> 对接文档描述协议规范, 本文档记录实际联调中的经验、问题与解决过程。

## 1. 飞控接入方式: 网口 ETH (UDP) 替代串口

### 1.1 当前方案

飞控通过 **RJ45 网线直连**树莓派 5 的 ETH 口, 走 **MAVLink over UDP**, 取代传统的 telem 串口。

```
树莓派5 (eth0 10.41.10.100/24) ──网线── X25 EVO飞控 (10.41.10.2/24, UDP 14550)
        │
        └─ wlan0 (上网/SSH) / wwan0 (4G)
```

### 1.2 树莓派 eth0 配置 (netplan)

文件: `/etc/netplan/90-NM-*.yaml` (Netplan 渲染的 NetworkManager 连接)

```yaml
network:
  version: 2
  ethernets:
    eth0:
      renderer: NetworkManager
      addresses:
      - "10.41.10.100/24"
      networkmanager:
        passthrough:
          ipv4.never-default: "true"
```

**关键设计**:
- 静态 IP `10.41.10.100/24`, 与飞控同网段
- **不设网关** + `ipv4.never-default: yes`: 保证 eth0 **永远不会**成为默认路由, 插网线不会抢走上网流量/SSH
- 上网始终走 wlan0 / wwan0

> ⚠️ 文档示例里的 `static routers=10.41.10.254` **不要配**: 直连飞控不需要网关, 配了反而可能让默认路由切到飞控网段导致断网。

### 1.3 飞控侧 net.cfg 配置

飞控 SD 卡 `/fs/microsd/net.cfg` (通过 QGC MAVLink Console 写入, 重启生效):

```ini
DEVICE=eth0
BOOTPROTO=static        # 直连无 DHCP, 用 static 立即生效 (fallback 会先等 DHCP 超时)
IPADDR=10.41.10.2
NETMASK=255.255.255.0
```

### 1.4 MAVROS fcu_url

`device_monitor.launch.py` 默认 fcu_url 已改为网口 UDP:

```
fcu_url: udp://:14550@10.41.10.2:14550
```

验证连接成功的标志日志:
```
CON: Got HEARTBEAT, connected. FCU: PX4 Autopilot
MAVROS UAS via /uas1 started. MY ID 1.191, TARGET ID 1.1
link[1000] detected remote address 1.1
```

## 2. fc_monitor 节点实现要点 (MAVROS 2.14)

### 2.1 版本差异: 消息名与文档不同

对接文档写的 topic 在 **MAVROS 2.14 中不存在**, 需按实际版本适配:

| 数据 | 文档 07 写法 (不可用) | MAVROS 2.14 实际 (已用) |
|------|----------------------|------------------------|
| 电机输出 | `/mavros/actuator_control/outputs` (ActuatorOutputStatus) | `/mavros/actuator_control` (ActuatorControl.controls[8]) |
| 空速 | `/mavros/airspeed/indicated_speed` (Airspeed) | `/mavros/vfr_hud` (VfrHud.airspeed/groundspeed/climb/throttle) |

### 2.2 启动误报缺陷 (已修复)

**问题**: 节点启动时未收到飞控数据, 初始值 0 会触发 altitude/battery 的 EMERGENCY 误报。

**修复**: 增加 `has_valid_data_` 标志, 收到任意 `/mavros/state` 才视为数据可用, 异常检测仅在 `has_valid_data_` 时执行。

```cpp
// 收到任意 state 即视为飞控数据可用
has_valid_data_ = true;

// 仅在有有效飞控数据时进行异常检测, 避免启动初期初始值误报
if (has_valid_data_) {
  run_anomaly_detection();
}
```

**验证**: 联调时 fc_monitor 收到真实数据后才告警 (电池 48.06V / 67%), 不再启动即误报。

## 3. MAVROS `std::future_error: Promise already satisfied` 排查

### 3.1 现象

MAVROS 节点偶发崩溃, 日志:

```
terminate called after throwing an instance of 'std::future_error'
  what():  std::future_error: Promise already satisfied
[ERROR]: process has died [pid XXXX, exit code -6]  (SIGABRT)
```

崩溃点多出现在请求 **home_position / 参数同步** 之后。

### 3.2 原因分析

- `std::promise` 被赋值两次 (`Promise already satisfied`) → 未捕获异常 → `terminate` → SIGABRT
- 属于 **MAVROS 自身并发缺陷** (home position / 参数请求的回调竞态), 非本项目配置错误
- UDP 链路下偶发出现, 串口也可能出现; 与是否网口无关

### 3.3 处理与兜底

- **现状**: 依赖 `respawn` 自动重启恢复 (launch 中 mavros `respawn=True` + systemd `Restart=always` 双保险)
- 重启后 MAVROS 会自动重连飞控 (`CON: Got HEARTBEAT`), 数据链路不中断
- **后续建议**:
  1. 若崩溃频繁影响稳定性, 升级 MAVROS 版本 (该 bug 在后续版本有修复)
  2. 短期可将 MAVROS 崩溃纳入监控 (monitor 节点对 MAVROS 进程存活做看门狗)

### 3.4 排查命令参考

```bash
# 查看服务日志中的崩溃与重启
sudo journalctl -u airship-device-monitor.service -f
sudo journalctl -u airship-device-monitor.service -n 100 --no-pager | grep -iE "future_error|HEARTBEAT|connected"

# 确认 MAVROS 已重启并重连
ps -eo pid,etime,cmd | grep mavros_node
```

## 4. 联调验证方法

### 4.1 数据链路验证

启动 systemd 服务后:

```bash
# 节点是否运行
ps -eo pid,etime,cmd | grep -E "mavros_node|fc_monitor_node"

# 服务日志确认 MAVROS 已连接飞控
sudo journalctl -u airship-device-monitor.service | grep "HEARTBEAT"

# fc_monitor 是否收到真实数据 (出现真实电压/电量告警解除)
sudo journalctl -u airship-device-monitor.service | grep "FC\]"
```

### 4.2 网络层验证

```bash
ip -br addr show eth0        # 应显示 10.41.10.100/24 UP
ping 10.41.10.2              # 飞控可达
ip route                     # 默认路由仍是 wlan0, 无 eth0
```

## 5. 已知环境限制 (TRAE 工具环境)

仅影响开发工具环境内的自动化操作, **不影响 systemd 实际运行的系统**:

- 工具沙箱禁止写 `~/.ros/log`: 在工具内启动 ROS 节点需设 `ROS_LOG_DIR=/tmp/roslog`
- 工具沙箱每个命令独立 DDS 网络: 无法跨命令 `ros2 topic echo` 观察其他终端启动的节点
- 联调观察应以 systemd 服务日志 (`journalctl`) 为准
