## 一、系统架构与数据流

### 1.1 总体架构（三层）

```
┌─────────────────────────── 采集层(只读, 不发控制指令) ───────────────────────────┐
│ bms_node(can1@500k)  mppt_node×2(can0@250k, addr 01/02)  dcdc_node(can0, 仅监听) │
│ backup_bms_node(RS485_2)  lora_node(RS485_1, Modbus 6节点)  fc_monitor(MAVROS)   │
└──────────────┬────────────────────────────────────────────────────────────────┘
               │ /bms/status /mppt/status /mppt2/status /dcdc/status
               │ /backup_bms/status /lora/samples /lora/summary /fc/status
┌──────────────▼─────────────── 仲裁层 ─────────────────────────────────────────┐
│ monitor_node(告警去重/看门狗)          safety_node(DCDC+BMS+备用BMS 三判据)      │
│ → /monitor/device_alert               → /safety/status (safe_to_control)       │
└──────────────┬────────────────────────────────────────────────────────────────┘
               │ 订阅各设备状态 + 告警
┌──────────────▼─────────────── 下行链路层 ──────────────────────────────────────┐
│ link_node(JSON打包, 串口+UDP双发)         cloud_node(MQTT/TLS 上云)             │
│ → 串口(调试通道) + UDP:20000(数传网口主通道) → EMQX Cloud:8883 → web dashboard  │
└──────────────────────────────────────────────────────────────────────────────┘
                 独立于 ROS2: dcdc_hold(systemd, 200ms 控制帧保活, 控制独占)
```

### 1.2 关键设计约束（验证均成立）

- 消息定义独立于业务包（airship_msgs），依赖严格向下 DAG
- 全部节点为只读监控，控制指令唯一出口是 dcdc_hold（独立进程，ROS 崩溃不断电）
- 串口设备用 udev 符号链接（/dev/airship_485、/dev/airship_backup_bms）
- MQTT 密码经 MQTT_PASSWORD 环境变量注入（EnvironmentFile root:600），不落命令行/明文
- CAN 波特率单一配置源 /etc/default/airship-can（本轮 E1 修复后闭环）
- 协议解析库无 ROS 依赖，节点层只做路由/聚合/发布
